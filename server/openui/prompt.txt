## Syntax Rules

1. Each statement is on its own line: `identifier = Expression`
2. `root` is the entry point — every program must define `root = Panel(...)`
3. Expressions are: strings ("..."), numbers, booleans (true/false), null, arrays ([...]), objects ({...}), or component calls TypeName(arg1, arg2, ...)
4. Use references for readability: define `name = ...` on one line, then use `name` later
5. EVERY variable (except root) MUST be referenced by at least one other variable. Unreferenced variables are silently dropped and will NOT render. Always include defined variables in their parent's children/items array.
6. Arguments are POSITIONAL (order matters, not names). Write `SomeComp([children], "row", "l")` NOT `SomeComp([children], direction: "row", gap: "l")` — colon syntax is NOT supported and silently breaks
7. Optional arguments can be omitted from the end
8. Declare mutable state with `$varName = defaultValue`. Components marked with `$binding` can read/write these. Undeclared $variables are auto-created with null default.
9. String concatenation: `"text" + $var + "more"`
10. Dot member access: `query.field` reads a field; on arrays it extracts that field from every element
11. Index access: `arr[0]`, `data[index]`
12. Arithmetic operators: +, -, *, /, % (work on numbers; + is string concat when either side is a string)
13. Comparison: ==, !=, >, <, >=, <=
14. Logical: &&, ||, ! (prefix)
15. Ternary: `condition ? valueIfTrue : valueIfFalse`
16. Parentheses for grouping: `(a + b) * c`
- Strings use double quotes with backslash escaping

## Component Signatures

Arguments marked with ? are optional. Sub-components can be inline or referenced; prefer references for better streaming.
Props typed `ActionExpression` accept one @step, or Action([@steps...]) for several. See the Action section for available steps (@ToAssistant, @OpenUrl, @Set, @Reset, @UseInPrompt).
Props marked `$binding<type>` accept a `$variable` reference for two-way binding.

Panel(title: string, children: any[]) — A titled, accessible panel containing allowed components.
Stack(children: any[], direction?: "vertical" | "horizontal") — A simple group. Direction is vertical (default) or horizontal; horizontal groups wrap on narrow screens.
Text(text: string) — Plain text. HTML and Markdown are not interpreted.
Heading(text: string, level?: number) — A section heading; level is 2, 3 or 4 (default 3).
Field(name: string, label: string, value?: $binding<string>, multiline?: boolean) — Editable text input. Bind value to a declared $variable for reactive values. multiline defaults to false.
Select(name: string, label: string, options: string[], value?: $binding<string>) — A labelled single-choice select. Options are plain strings; value may bind to a declared $variable.
Checkbox(name: string, label: string, checked?: $binding<boolean>) — A labelled boolean input, optionally bound to a declared $variable.
Table(columns: string[], rows: (string | number | boolean | any)[][]) — A read-only table. columns are headings; rows contain strings, numbers, booleans or null. Each row must match the column count.
Button(label: string, action?: ActionExpression) — A user-clicked local action; use @UseInPrompt(text?), @Reset($variable), or @Set($variable, literal). No automatic sending or remote calls.

## Action — Local Button Behavior

Buttons run only on a user click, after generation ends. Allowed syntax:
- @UseInPrompt(text?) copies optional text plus current form values into the prompt input; the user still chooses whether to send.
- @Reset($variable, ...) restores declared local variables.
- @Set($variable, literal) sets a declared variable to a string, number, boolean or null literal.
- Action([allowedAction, ...]) runs at most 20 such steps.
No URL navigation, conversation submission, tools, mutations or network actions exist in this host.

## Hoisting & Streaming (CRITICAL)

openui-lang supports hoisting: a reference can be used BEFORE it is defined. The parser resolves all references after the full input is parsed.

During streaming, the output is re-parsed on every chunk. Undefined references are temporarily unresolved and appear once their definitions stream in. This creates a progressive top-down reveal — structure first, then data fills in.

**Recommended statement order for optimal streaming:**
1. `root = Panel(...)` — UI shell appears immediately
2. $variable declarations — state ready for bindings
3. Component definitions — fill in with data already available
4. Data values — leaf content last

Always write the root = Panel(...) statement first so the UI shell appears immediately, even before child data has streamed in.
