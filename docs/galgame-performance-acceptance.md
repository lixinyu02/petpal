# 二次元台词演出验收

2026-09-30，issue-40。网页已发布；本轮未重新制作 Android、Windows 或 Ubuntu 安装包。

## 表情与动作

保留同一位奶油白／浅橘伙伴，在已有表情上加入小得意、轻微鼓腮、安心与认真。赞同点头、否定摇头、好奇侧倾、害羞回避、开心轻跃、惊讶后仰与安心放松均为单次动作，有起势、保持、收尾和冷却。相同台词增量不会重复触发，被中断的动作不补播。

语音播放进度仍选择当前分句的表情，口型最后合成。文本演出不需要声音；本轮没有宣称新增语音情绪控制或精确音素识别。直接触碰沿用既有入口，没有增加产品中的表情按钮。

## 自动验证

- 230 项控制器、语义、动作、渲染、资源、头发与语音相关回归通过，无跳过。
- 公网触摸时进一步发现笑眼强度不足导致持续双眼重影；修复后对应渲染文件 9 项测试通过，新增测试使用真实触摸控制器，验证闭合眼睑保持至少 250 ms，害羞保持睁眼。
- TypeScript 和最终隔离 Vite 构建通过。既有 3D CompanionScene 分块大小提示仍存在，非本轮二次元渲染错误。
- 低帧率回归覆盖每秒一帧时动作按实际时间结束、冷却释放、表情与头姿收回。局部物理和文字嘴型积分继续有界。

## Chrome 验收

在 412×960 和 1280×900 视口验收。四种新表情可辨识；七类单次动作有不同姿态，并在结束后回到静止动作通道。人物、头颈与服装保持对位，未见横向溢出。

手机尺寸下多组 3.6 秒采样得到约 92–96 个不同渲染帧，符合当前 30 fps 上限附近的表现。首次观察到每秒一帧，实测来自 Chrome 窗口遮挡节流，前置窗口后恢复；不能把这个结果当成 Android 或 Ubuntu 实机性能验收。

主动丢失 WebGL 上下文后，DOM 人物、鼓腮、摇头与嘴型仍可见；阻断可选 pout 贴图后，基础人物继续使用 WebGL。减少动态效果时身体动作和点头均为零，文字嘴型仍工作。所有临时视口、媒体与资源阻断设置已清除。

公网登录后，在 412×960 直接触摸人物头部，确认 pet → happy + tilt，最终笑眼无持续重影。测试会话已通过界面退出；没有发送聊天或 Agent 任务。截图与动作采样仅保存在忽略的本地 evidence 目录。

## 部署与数据

使用隔离构建、保留旧资源、原子替换 HTML 的方式部署；最终公网 HTML、15 个 JS/CSS/表情资源与构建哈希一致，动态人物模块为 `AnimeScene-NKiZiQoW.js`。TLS 使用正常证书与主机名验证。

六个匿名语音接口均为 401。部署时生产 state 哈希未变；整轮验收复核账号、模型、聊天、语音配置和执行主机数据未变，仅测试登录会话的生命周期变化。后端没有为前端发布而重启。
