# 把 PC 作为中央服务器

Windows / Ubuntu 的中央服务器模式复用电脑客户端内置的完整后端。连接这台电脑的设备共用这里的账号、模型授权、聊天记录、语音配置和 Agent 执行电脑列表。它是一套独立服务；既有公网服务器的数据不会自动复制到电脑。

此原生功能需要包含 `centralServer` 桥的新桌面客户端。既有正式 0.9.7 安装包不包含该桥，仅刷新网页不能给旧安装包增加监听能力。本轮源码与原生验收不替换现有 Release。

## 开启

1. 在电脑客户端登录页面选择“以本机管理员身份登录”。正在使用远程服务时，可在“设备连接 → 中央服务器 → 登录本机管理员”打开登录窗口，再选择本机管理员。
2. 在“账号”中为本机 `owner` 设置密码，并按需创建成员、分配模型和 Agent 权限。本机配对令牌不能在中央入口使用，分享地址不包含令牌。
3. 在“设备连接 → 中央服务器”启用服务，选择端口，点击“保存服务设置”。默认端口为 4319，避开现有独立后端默认 4318；被占用或浏览器限制的端口不能使用。
4. 状态显示“正在监听局域网连接”后，复制下方局域网地址。其他电脑客户端或同网网页访问此地址，使用这里的账号密码登录。
5. 需要让另一台电脑执行任务时，在另一台电脑的客户端连接本中央服务并登录同一账号，再在 Chat + Agent / Agent 中选择这台执行电脑。选择执行电脑仍遵守管理员分配的权限。

中央服务器只负责本机服务共享，不替代操作系统权限。入站连接仍需网络和系统防火墙允许该程序或所选 TCP 端口。更改端口失败会保留原服务；成功后其他设备需使用新地址。

## HTTPS 与 Android

局域网 HTTP 支持网页 Chat / Agent、朗读播放及其他 PC 客户端连接。浏览器的麦克风、摄像头与 Android 安装版需要可信 HTTPS。不要关闭证书校验或全局允许安卓明文来代替 HTTPS。

已有可信 HTTPS 反向代理时，将其固定入口填入“HTTPS 访问地址”，例如 `https://pet.example.com:44318`。入口只能包含协议、域名及可选端口，不能包含 API 路径、密钥或查询字段。反向代理上游为 `http://<此电脑地址>:<局域网端口>`，完整保留请求 Host、Authorization、流式正文和 Range，不缓冲 SSE/语音。保存入口只声明允许的来源，不会创建证书、配置代理或开放公网端口。

额外中央入口允许此精确 HTTPS 来源和 Android 固定 `https://localhost` 来源，本机 loopback 页面不扩大 CORS 权限。公网反向代理、证书、远端访问和物理设备语音仍需在实际部署上验收。

## 运行与停用

开启设置保存到这台电脑，之后小伴启动时会恢复。可以搭配“启动与窗口”的开机自启和启动时收起到托盘设置；系统休眠、关机或彻底退出小伴时服务停止。关闭主窗口且启用了“关闭到托盘”时，后台服务继续运行。

关闭中央开关并保存，会断开中央入口的外部连接；本机窗口、账号数据和内置后端保留。已经提交的 Agent 任务不会因关入口而自动取消，任务结果仍保存在原会话中。若要停止任务，先在任务界面停止；彻底退出小伴则关闭服务器与执行器。

监听状态、保存的开启设置、可信 HTTPS 入口配置和另一台设备实际连通分别显示或验证，不能互相替代。恢复失败会保留数据和配置、显示原因，本机聊天仍可继续使用。
