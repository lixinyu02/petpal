# 同账号执行电脑验收

## 功能范围

执行电脑来自登录同一中央服务、同一账号的 Windows / Ubuntu 客户端。Web、Android 和桌面工作台使用独立主机选择器，不通过切换后台实现。队列条目冻结电脑，审批、插入指令和停止路由到已捕获的执行连接。正常退出等待本机 CLI 停止；断网或崩溃无法确认时显示执行状态未知，暂停且不重放。

中央保存聊天和模型权限。切换执行电脑保留同一会话消息，在新电脑创建 Codex thread，并带入最多 12,000 字符的近期文字（整个 prompt 不超过 32,000 字符）；不会跨电脑 resume thread。文件、图片工作路径和运行环境不随历史迁移。重复提交不重复执行。

上游 API 密钥留在中央；执行电脑使用限定账号、连接、运行和模型的短期 Responses relay。图片按运行授权下载和校验，并在 CLI 关闭后清理。账号无 Agent 权限时不能登记电脑；成员不能通过空模型参数绕过管理员分配。

## 自动化与真实 CLI

相关测试覆盖稳定设备身份、账号/中心隔离、旧连接拒绝、持久命令回执、图片归属、停止确认、断网未知状态、队列暂停、模型范围与原接口兼容。全量 Node 测试 515/515、TypeScript 和 Vite 构建通过；318 文件公开源码索引审计通过。

集成测试使用真实 HTTP 中央协调器和两个 DesktopExecutor，但以可控制的 CLI fixture 检查精确目标、审批、插入指令和取消；不是单纯检查 UI 标签。

2026-09-29 的独立真实链路验证使用同一台 Windows 上两个隔离数据目录、两个真实 CodexBridge 和 GPT-6 Luna。A→B→B 三轮分别收到指定的 `PETPAL_REMOTE_REAL_1_OK`、`PETPAL_REMOTE_REAL_2_OK`、`PETPAL_REMOTE_REAL_3_OK`。两套执行器均发出 thread/turn/delta，中央同一会话消息从 2 条变为 4 条、6 条；第三轮成功 resume B 电脑的原生 thread，原始 API Key 未传入任一执行器。请求采用只读权限，仅要求文本回复，没有操作用户文件或软件。此证据不能替代两台物理电脑或 Ubuntu GUI 实测。
