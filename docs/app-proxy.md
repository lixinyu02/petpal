# 小伴桌面应用代理

Windows / Ubuntu 客户端内置 Clash 兼容的 Mihomo 1.19.32。默认关闭，配置不附带节点或订阅。

## 使用

连接客户端的本机服务并登录本机主账号，进入「连接与设置 → 设备连接 → 应用代理」。导入 `.yaml` / `.yml`，或展开「粘贴 YAML 配置」保存。配置上限 4 MiB；通过内核校验后才替换原配置。启用期间先关闭代理再导入新配置。

点击「启用代理」，可切换配置中的手动选择节点组。勾选「随小伴启动」仅在下次打开小伴时启用内核；它不创建系统开机启动服务。需要整个客户端开机启动时，另外使用原有「启动与窗口」设置。

代理仅服务于小伴的模型、官方账号、服务/下载请求及其 Chromium 窗口。局域网 CPA、ASR/TTS、执行电脑和本机私有网关默认直连。公开 ASR WebSocket 也接入代理。不会修改系统代理、DNS、路由或防火墙，不使用 TUN，不要求管理员提权。

内置 Codex API/官方模型请求经小伴的私有网关转发。OpenCLI 查询每次启动独立 Node worker，显式适配代理。新启动的 Codex/MCP/ncm 运行时收到受控本机代理环境；第三方运行时是否采用这些环境变量由其实现决定。已有工具进程保留启动时环境，切换代理不会为此终止正在进行的任务；手动 ncm 配置向导不会把临时代理凭据写入持久文件。外部 Chrome 的网站操作仍使用 Chrome 自身网络设置。

关闭、更换或异常退出内核时，不会自动重发模型请求或工具任务；受影响的流会结束，可检查结果后手动再提交。

## 配置与隐私

配置保存在当前客户端用户目录的 `app-proxy/config.yaml`，启动偏好为同目录 `settings.json`。运行配置包含随机本机认证，只在主进程使用，退出时清理；节点密码、原 YAML 和控制器凭据不返回页面或中央服务器。Linux 目录/文件分别收紧为 `0700` / `0600`。原配置中的 TUN、额外入站、系统网络和公网控制器选项会被禁用；文件型 provider 需先合并到 YAML，远程 provider 缓存限制在私有目录。

导入或内核启动成功，只证明配置与本机代理就绪，不保证所选节点或外部服务可达。需要导入自己的有效配置后验证实际连接。开发/验收使用的本地模拟节点不提供公网代理服务。

## 平台与分发

内核固定支持 Windows x64 / ARM64、Linux x64 / ARM64；x64 采用兼容指令集版本。客户端和内核必须使用同一平台架构。网页和 Android 不启动本地代理内核；下载中心按实际已发布的平台/架构列出客户端。

核心未修改，以独立进程随包提供；包内 `mihomo/` 保留 GPL-3.0 LICENSE、来源与对应版本的源码、官方 vendor 压缩包。核心仅随小伴版本更新，不调用上游内核自升级。
