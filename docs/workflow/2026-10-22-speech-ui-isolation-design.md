# 语音播放期间的页面流畅性优化

- Date: 2026-10-22
- Complexity: L1
- Status: completed; source and isolated acceptance only

## Background

基线3864bbb已优化回复收尾、Markdown节点和隐藏轮询。新的源码检查发现，CosyVoice播放器每40ms上报完整状态，useSpeech将每次音量/字符进度写入React state；App直接消费该hook，因此口型进度会带动整个工作区执行渲染。历史列表已memo，不重复宣称其缺失。

## Goal

让高频口型、音量及情绪进度仅更新人物子树，停止/出错/缓冲等状态仍及时更新按钮和界面。保留语音完成等待、权限、账号隔离及现有默认hook调用行为。

## Non-goals

不调整TTS/ASR服务、音频采样或动画帧率；不替换正式包、生产服务、模型资产或发布清单。不用合成音频进度测试冒充真实声音或手机性能。

## Solution

为useSpeech加入可选的独立进度通道。完整不可变快照由实例私有订阅保存，App只在控制状态变化时更新；人物组件直接订阅完整快照。其他useSpeech消费者默认保持原行为。人物输入与交互回调使用稳定引用，输入草稿不会重新运行人物组件。账号/配置切换和卸载重置进度，旧控制器回调不能污染新实例。

## Impact

useSpeech、App和一个人物订阅组件；不改API、存储及播放控制器协议。

## Risks

停止、结束、缓冲、出错、语言进度来源改变不能被误判为纯进度；完成awaiter必须看到每个原始状态。隐藏/账号切换后的进度必须清理，订阅必须可取消。高频订阅不得重新安装音频播放器或重建WebGL模型。

## Verification Plan

先记录基线。用真实hook与人物组件的隔离回归覆盖进度、状态边界、停止、换账号与卸载；Chrome运行真实App并注入明确标记的本机合成朗读进度，对照App执行次数及人物进度，验收输入、停止按钮和412×960布局。执行相关语音/人物/消息回归、类型检查、隔离构建和源码审计，保留原始数据。浏览器计数只代表受控调用，不代表FPS、真实音频质量或手机实机。
