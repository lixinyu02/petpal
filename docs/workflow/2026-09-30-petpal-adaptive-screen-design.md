# 412×960 竖屏与跨端自适应

- Date: 2026-09-30
- Complexity: L1
- Status: updated

## Background

用户要求宠物与部分 UI 随屏幕大小适配，重点尺寸为 412×960，使用 Web、Ubuntu 和 Android。当前陪伴页混有多个固定高度，工作台的小伙伴固定为 60×70；Electron 主窗口最小 760×540 会超出窄竖屏。

## Goal

以实际可用视口和角色容器尺寸布局：竖屏陪伴角色完整且比例自然；Chat/Agent 可读可触控，键盘或矮窗口下输入区可达；Ubuntu 窗口和悬浮宠物约束于显示器可用区域；Android 保留安全区和窗口尺寸变化兼容。

## Solution

- 视觉：延续奶油白与绿色，角色居中且留出足够空间，操作区紧凑清晰。
- 内容：陪伴页由顶部导航、标题/切换、弹性角色舞台、回复/交互提示和底栏组成，按可用宽高共同缩放。
- 交互：保持角色直接触摸、抚摸与表情；使用已有动画，不引入额外装饰动画；弹层、模式/模型/主机入口与停止保持可达。
- 共享前端覆盖网页、Electron 与 Capacitor；必要时补充可视视口高度和 Android adjustResize，缩放不禁用。
- 原生窗口尺寸使用工作区边界，响应小屏、缩放与显示器变化，不改 Agent、鉴权、LLM 或语音协议。

## Scope and Risks

先上线网页；Ubuntu/Android 原生源同步适配，按照此前偏好不重做安装包。区分 CSS 像素与物理像素，以运行时可用视口为准，不硬编码唯一设备型号。避免窄屏裁切角色、键盘挤出输入框、安全区重复和桌宠越界。未有对应设备实机证据时明确标注。

## Verification Plan

Chrome 插件：412×960 重点验证两种伙伴、首页、Chat、Agent、设置和菜单；兼查 360×640、412×560（缩短视口）、960×412、1280×800。测无横向溢出、角色不裁切、操作按钮和弹层可达、两种角色切换/触摸不回归。TypeScript/隔离构建与原生窗口边界测试；可用时做 Android 编译检查。隔离预览通过后备份上线，保留所有生产数据和配置。
