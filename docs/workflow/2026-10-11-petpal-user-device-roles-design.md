# 用户身份与执行设备权限

- 日期：2026-10-11
- 复杂度：L2
- 状态：完成，网页与当前中央后端已部署并通过真实接口及 Chrome 验收

## 背景

现有账号仅 owner 为管理员，成员可按 agentAccess 使用中央服务器。设备按账号登记，但管理员也只能看自己的 PC。用户要求加入用户／管理员身份，普通用户只能执行自己登录的 PC，管理员可见和选择全部设备，Codex 权限选项全部开放。

## 目标与范围

角色统一为 user/admin；旧 member 迁移为 user，owner 继续 admin。管理员可创建和调整账号身份、模型授权、密码及停用状态，owner 不可停用或降级。全部有效账号拥有 Agent 完整访问能力，保留每次任务的只读／工作区／完整访问、询问／自动运行／模型审查选择及执行器能力检查。模型授权和聊天私有性保持按账号。

普通用户只可见、选择自己的 PC；管理员可见中央服务器与全部账号 PC，设备列表显示所属账号。PC 登记及长连接仍由原登录账号持有，管理员可派发但不能伪造别人的心跳、取件或回执。

## 实现

统一角色和设备访问函数，用于设备目录、目标解析、任务启动、运行中模型转发、队列、Chat + Agent、默认执行设备及自动化授权。旧版直接中央 Codex 消息入口显式校验中央权限，缺省 hostId 不成为绕过入口。

持久化记录仅验证历史目标存在，当前角色权限在实际操作时重新校验；管理员降级撤销登录并停止任务，历史仍可加载。升级备份旧身份数据，普通用户不可访问的默认电脑清为 null，不自动切换到其他电脑。按用户补充，普通用户界面直接隐藏中央服务器和他人电脑，旧失效选择不合成列表项，等待选择自己的 PC。

## 影响与风险

既有成员中央任务将不能继续提交，须在自己的 Windows/Ubuntu 客户端登录并保持在线。已有客户端收到新的角色和设备列表后仍受服务端校验；新版完整身份管理 UI 先部署网页，原生包未重打。放开的是 Codex 执行选项，非账号、设备、模型、会话和文件归属隔离。

## 验证

覆盖角色管理、中央／跨账号拒绝、自己的 PC 完整访问／自动运行、管理员全部设备派发、长连接凭证归属、降级停止与历史重启、Chat + Agent／队列／自动化／旧入口／默认电脑绕过。运行相关回归及前端构建，隔离执行器验收，部署前备份并确认空闲，Chrome 检查普通用户与管理员视图。
