# 语音打断与后台任务回报

- Date: 2026-10-06
- Complexity: L1
- Status: verified and deployed

## 现状与目标

现有语音状态机为半双工：识别、思考和朗读阶段停止麦克风，只有按钮可以打断。后台 Agent 的终态已可幂等追加父 Chat，但依赖 GET 刷新；模型生成前没有主动刷新任务，长任务没有主动回报，语音界面仅更新任务卡。

## 方案

继续使用当前登录、麦克风选择、ASR、流式 Chat 与 CosyVoice。回答时保留本机麦克风及浏览器回声消除，以更严格的持续语音门限识别插话，保留起始音频后进入正常 ASR。取消当前 Chat、TTS 和排队句子，旧回调由序号与账号会话隔离；等前次流结束后再发送同会话新消息。按钮打断继续可用，关闭页面、换设备、换账号必须结束收音。

后台协作增加不依赖页面的周期 reconcile，仅更新已派发任务，不调用模型、不重派任务。执行超过约30秒给首条进度；后续间隔至少2分钟并限制条数。进度只说明当前已知排队/执行/确认状态，最终结果保留真实完成/失败/取消/未知区别。消息以任务与回报类型标记，保存失败可重试，重复轮询或服务恢复不得重复插入。下次 Chat 请求在上下文生成前取得最新状态，普通聊天也能知道之前的任务。

前台将新增回报显示为普通可朗读消息；开启语音对话时，新回报在用户没有说话且当前回答结束后播放。用户插话优先，已开始的回报可被打断，不重复朗读历史结果。页面切换、账号切换、持续回答期间的消息合并不能丢掉本地流式文字或重复播报。

每次显式开启语音时，首轮发送前读取同会话回报基线；后续只播报新报告。长结果转为最多800字符的纯文字摘要，完整消息保持不变；控制器的有界队列之外保留有界待播缓存，容量恢复后继续投递。服务端 meta/done/error 提供本轮 assistantMessageId，避免后台回报成为末条消息时误选前台回复。实际 ASR 的尾部 [Silence] 标记在边界清除，纯静音不发送给 Chat。

## 验收与发布边界

覆盖持续说话、静音/短噪声、旧流迟到、语音/任务通知并发、保存失败/重启幂等、权限撤销与并行 Chat。运行相关回归、类型检查、隔离构建、真实上游链路及 Chrome 入口验收。先更新网页与后端，共享源码同步 GitHub；现有0.9.9安装包不在本轮替换，Windows/Ubuntu源码的运行验收与手机实机验收分别记录。

## 最终证据与限制

375项定向测试通过，类型检查与隔离Vite构建通过。真实CosyVoice生成的两段PCM经实际ASR、Chat与浏览器流式播放运行15.267秒：播放期间注入插话，526ms后旧Chat/TTS取消，收到停止回执，新问题完整识别并朗读5，无409冲突。输入为测试音频，实体扬声器回声与各手机实机效果未验收；回声抑制使用现有浏览器AEC和能量门限。

隔离真实HTTP验收在30.111秒主动持久化进度，完成结果幂等，重新加载存储及下一轮普通Chat上下文通过。真实生产Chat→Agent验收也在没有前台GET轮询时保存进度和唯一结果，下一Chat读取状态与标记且未重新派发；实际计时命令被执行策略阻止，不能用Agent运行时长宣称命令成功。回报中的completed表示该Codex轮结束，具体操作结果仍依据正文。

公网HTTPS网页/后端已部署并重启，412×960 Chrome语音界面无横向溢出，收音已结束。15个下载文件和4份发布元数据保持不变，0.9.9安装包未重打。一次高并发重复回归停滞，单独CosyVoice测试13/13及受控并发最终375/375均通过，停滞原因未证实。开发验收曾出现音频ACK超时，直连/代理实时分块和隔离构建Chrome复测均通过。
