# 手动修正记忆

- Date: 2026-10-25
- Complexity: L2
- Status: final

## Background

已有账号隔离的记忆搜索和选择性删除；用户需要修改错误事实。Memobase 正在异步提炼历史，直接修改上游 profile 会被重写，且 PC 离线缓存可能复活旧内容。

## Goal

用户在设置的记忆列表中编辑单条正文，保存后 Chat/Agent 和同账号设备优先使用修正内容，取消不写入。

## Non-goals

不改历史原文，不重新提炼全库，不修改他人资料；不新增离线管理写入队列。

## Solution

中央账号 journal 保存权威人工修正层，与原 profile 使用同一 ID，标记手动修正和修正日期。首次编辑同时记录原 profile 的遗忘指纹和内容摘要，沿用已有选择性召回过滤，防止旧摘要和历史原文补回。人工修正先于自动提炼条目进入召回；再次提炼不会覆盖修正层。

编辑请求携带 epoch、ID、fingerprint 和新正文；持久化队列内再次校验，拒绝过期或其他账号条目。人工层单调 revision 与下行同步、缓存和并发召回校验相连；清空时一并清除，删除支持手动条目。PC 在线转发中央，离线按最后同步的修正召回，管理需中央可达。

## Impact

修改记忆服务、HTTP API、同步协议的可选字段、设置列表和实际处理函数测试；现有 journal 缺少新字段时默认空层。需要受控重载小伴后端和发布网页，不重启 Memobase 或修改学习偏好。

## Risks

同步迟到不得回退人工修正 revision；缓存迟到不得提交旧摘要；编辑/删除竞态必须在原子写入时复验；正文是数据，不赋予工具权限。限制单条 6000 字并去除凭据，拒绝空白，不静默截断。

## Verification Plan

合成资料覆盖隔离、冲突、取消、再次编辑、删除、重启、旧摘要迟到、PC 同步/离线、旧 snapshot、清空和换账号；Chrome 验证实际编辑保存。生产只读验收和业务/记忆事件保留，不修改真实用户记忆。
