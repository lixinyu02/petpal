# 页面启动与状态写入性能

- Date: 2026-10-23
- Complexity: L1
- Status: final

## Background

当前存储为 JsonStore 整体状态文件，每次逻辑保存均捕获快照、执行扩展、序列化、fsync 与原子替换。不能直接合并逻辑保存：通知依赖中间完成状态，操作还包含延迟权限校验。会话元数据提交含嵌套查找。前端启动为登录验证、页面模块、初始状态的串行链路。

## Goal

减少实际写入体积和相同内容重复落盘，降低会话整理随历史规模增长的开销；并行准备已验证账号的页面模块与初始数据，缩短可交互等待。

## Non-goals

不迁移数据库、不牺牲fsync、不丢弃逻辑保存或通知事件；不重写语音状态机或音频手势，不修改主题与功能，不重打客户端。

## Solution

issue-1：紧凑JSON；仅对完全相同的准备结果且文件身份/大小/纳秒时间戳保持时省去物理写入。所有prepare、beforeCommit与commit语义保持；任何文件不确定性回到正常原子写入。会话查找使用保持首匹配语义的Map/Set。

issue-2：验证登录成功后立即并行预载所选页面和对应bootstrap/state；预载结果短时、单次、按账号epoch及history模式隔离，取消/错误/超时/404兼容保持。未验证账号和原生被动悬浮窗口不预取私人状态。

Chrome另确认工作台初始state为约111KB未压缩响应。仅为鉴权后的GET /api/bootstrap与GET /api/state增加协商压缩，保留no-store，不处理SSE、语音流、上传、下载、Range或鉴权失败响应。避免慢网络等待完整历史传输。

## Risks

无操作写入仍须满足授权与持久化边界；文件外部删除/替换不得被缓存掩盖，失败不得污染后续缓存。前端不得复用跨账号数据、吞掉失败或让未消费请求永久存活。

## Verification Plan

合成隔离数据前后对照：重复/变化保存、物理写入次数、文件体积、会话索引伸缩；失败/授权/事件顺序/关闭回归。前端按同网络条件采集Chrome启动，验证并发请求、单次消费、账号切换、取消、过期、缺失端点与真实页面/聊天；TypeScript及生产构建，发布后核对账号配置和下载文件。
