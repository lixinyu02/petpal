# 二次元伙伴的台词演出

- Date: 2026-09-30
- Complexity: L2
- Status: completed；语音服务恢复范围见独立稳定性记录

## 背景与目标

用户希望人物进一步接近 Galgame 的表情和动作演出。在既有开心、伤心、难过、兴奋、害羞基础上，新增小得意、轻微鼓腮、安心与认真；让一段台词有反应起势、短暂保持和缓和收尾，而不是不断循环摇晃。同一奶油白／浅橘角色、原有触碰互动与网页优先发布的偏好不变。

## 视觉与交互

- 视觉主张：保留温柔人物和安静舞台，让面部变化与小幅身体动作承担演出，不堆表情按钮或常驻装饰。
- 内容结构：伙伴页和 Chat/Agent 角色共享控制器；每句台词的语义驱动当前情绪，TTS 以当前朗读位置驱动相同表演。验收面板仅本机使用。
- 动作主张：赞同点头、否定摇头、好奇侧倾、害羞回避、开心轻跃、惊讶后仰、安心放松。动作有冷却和去重，台词增量更新不反复触发同一动作；不同语义之间平滑过渡。

## 实现方案

表演控制器增加 bounded 的动作通道 bodyLean/bodyLift/bodyTurn、headShake，并输出 gesture/gestureProgress 便于验收。动作不改变发音口型；停止、缓冲、页面隐藏、低动态和睡眠受既有生命周期约束。现有 headTilt/headNod 与头发惯性保持兼容。

新增 smug/pout/relieved/determined 文本表情，保守处理否定、安慰和枚举。现有语义选择器继续只看当前句/分句。补充同角色精确对位 pout 素材，最多八张采样贴图，加载失败时只损失附加表情。WebGL 与 DOM 使用共用表情映射，身体动作有相同方向与上限，优先避免颈部扭曲和人物出框。

## 范围与边界

本轮不更换角色、不增加 UE/Cubism、不制作安装包、不修改 LLM/API 协议、不宣称 TTS 可控制声音情绪。此前用户要求的 ASR/TTS 稳定性排查作为服务恢复工作并行进行，诊断与实际合成结果单独记录，不能用表演预览代替真实音频验收。

## 风险与验证

主要风险是动作被逐字重复触发、情绪覆盖嘴型、新图片错位、移动采样器预算和降级丢失表演。用控制器时序测试验证单次触发、冷却、切句、长句、隐藏/停止/低动态；渲染映射和资源回归；TypeScript 与隔离构建；Chrome 桌面和 412×960 实际截图/动作采样，WebGL 丢失与缺少新贴图时仍可见。真实语音服务若未恢复须明确报告。

网页部署沿用隔离构建、旧资源保留、HTML 原子替换，完整核对生产账号/配置/聊天未变，检查公网资源和匿名语音门禁后提交源码。
