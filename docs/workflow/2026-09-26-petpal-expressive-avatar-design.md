# 小伴微表情与可开关朗读

- Date: 2026-09-26
- Complexity: L2
- Status: final
- Target version: 0.3.0

## 背景

0.2.0 已交付可切换的原创二次元伙伴与 3D 小猫，包含 Web、Windows、Android、Ubuntu x64/ARM64 产物。少女通过三张透明 PNG 的眼睛/口部局部混合与 40×60 网格形变实现呼吸、眨眼、转头、头发摆动和互动口型。它没有 Cubism Core、`.moc3`、语音朗读或音素级唇形同步。已有交付事实保留在 [验收记录](../acceptance.md)；本设计独立记录 0.3.0 开发，不将旧包视为已经升级。

用户继续要求更自然的微表情以及可开关的朗读。表情需要同时兼顾文字/语音状态、隐藏/恢复、资源加载与桌面小窗性能，朗读涉及浏览器和系统音色差异，因此采用 L2。研发保持单一 `issue-4`，在同一实施范围内分工渲染、朗读、性能和交付文档。

## 目标

1. 在已确认的原创成年少女形象上增加细腻、连续的面部表达，使安静、注意、思考和回应状态可区分，避免整幅立绘跳帧与脸部错位。
2. 提供默认关闭的自动朗读开关，以及停止、朗读上一条操作；开启后只朗读成功完成的助手回复。
3. 由真实朗读事件驱动口型与状态，并诚实呈现估算口型的边界；文本展示、生成取消和现有会话行为保持可用。
4. 控制持续陪伴的渲染开销，隐藏页面暂停，低动态设置有效；任何阶段仍只存在一个活动角色画布。
5. 以 0.3.0 独立记录构建和验收，保留 0.2.0 安装包、源包及已取得的结果。

## 非目标

本轮不接入 Cubism SDK、第三方 `.moc3` 模型、麦克风、语音识别、远程 TTS 或收费语音服务；不宣称声学音素识别或完整口型同步。用户配置的 Chat Completions / Responses、Codex app-server 协议与只读默认值不变。不操作 RK3566 实板、固件或既有本地服务数据。

## 方案

### 微表情与资源

在现有 `AnimeScene` 与独立角色适配入口上延续二维网格形变。新增资产必须来自同一原创人物，保持画布、脸部位置、透明边缘和肤色一致。眼睛、眉毛、口部等区域通过局部遮罩/混合权重组合；呼吸、轻转头和发丝沿用连续时间驱动，不把完整立绘当作交替动画帧。具体表情纹理名与权重由实现和截图确认后写入最终记录。

表情状态接受页面的等待、文本回复、真实朗读、互动和休息信息，以有限幅度平滑过渡。当前实现提供 neutral、warm、curious、thoughtful、surprised、shy，通过聊天状态与常见词句作轻量表情提示；口型使用 rest/A/E/O/M 的近似形状，不作语义情绪识别或汉字读音识别声明。闭眼休息优先于持续说话；不能因为存在待朗读文本便一直张嘴。切换为小猫时卸载少女渲染器，保留既有小猫造型、四足步态与聊天/Codex历史。

运行时纹理为原有 idle/blink/talk 加新增 round/curious/warm，仍只在局部遮罩内混合；其真实提示词分别见 [0.2 基线](../avatar-art-prompts.md) 与 [0.3 新增](../avatar-expression-prompts.md)。最终资产字节以冻结后的各端回执为准。

### 朗读控制与语音边界

使用浏览器系统 `speechSynthesis`，自动朗读默认关闭，由明确操作启用。提供自动朗读开关、停止和朗读上一条。只将当前成功完成的助手回复分句播报，不逐 token 朗读，不把失败、取消、历史加载或重绘当作新回复。朗读选项与现有角色偏好/会话身份区分，避免刷新、切会话或组件重建重复播报。

只选择 `localService=true` 且匹配文本语言的系统 voice；中文回复没有本地中文音色时给出明确提示，不回退到远端 TTS。`speechSynthesis` 不存在、WebView 不提供引擎、策略/用户激活限制或引擎报错时保留文本功能，并显示可理解的原因。可用音色由用户设备决定，Web 接口存在不等于已能出声。

口型优先消费引擎 `onboundary` 的 UTF-16 文本进度；引擎不提供边界时，只在真实 `onstart` 后根据句内文本和时长估算开合。估算必须与真实语音状态区分，界面和验收不得称为音素级同步。没有发声、已停止或出错时，口型及时回到静止。

取消生成、停止按钮、切换会话、离开页面、页面隐藏、卸载及切换到猫，都取消当前 utterance/后续队列，移除监听器与定时器。过期事件不得恢复已经停止的口型或驱动下一次会话。异常路径与显式停止共用清理流程。

### 性能与生命周期

独立 `performance.mjs` 管理表情与口型的演出状态，并以有界字符队列、时间步和已消费消息记录限制积压与重复播放。渲染仍控制像素比和更新频率，区分可见、隐藏、低动态与小窗状态，避免动画循环重复创建、每帧纹理/材质分配或隐藏后持续更新 GPU。恢复可见时重置时间基准，不补算后台积累帧。

停用与卸载应清理 RAF、观察器、监听器、几何、材质、纹理和 WebGL context；朗读资源由自己的生命周期管理。Android 独立悬浮 WebView 继续仅使用 APK 内资源、无 native JS 桥、无网络回退；不得为了发声扩大其权限或放宽 CSP。

### 版本与归档

项目及 lockfile 根版本为 0.3.0，Android `versionName=0.3.0`、`versionCode=3`；后端健康与 Codex clientInfo 同步版本元数据。发布清单从 `package.json.version` 推导五个平台/源码产物名，不再固定为 0.2.0；最终回执的版本、文件名、长度和哈希须对应当前产物，不能复用旧回执冒充验收。

源码白名单继续递归纳入 `src/avatar/` 与 `public/avatars/`，排除运行数据、凭据、私有日志、构建工具和 SDK。新增 PNG 必须在原生包和源码包的资源校验中出现；Linux 基础角色纹理校验不能因版本升级被跳过。冻结前不制作最终包、不改写 0.2.0 验收结论。

## 影响

前端影响角色表情渲染、App 朗读操作/状态与独立性能辅助模块；原生壳继续消费共享界面。后端运行逻辑不因朗读改变，版本字符串属于元数据同步。已有两协议、鉴权、持久化与真实 Codex 流程继续作为回归范围。公开项目研究沿用 [avatar-research.md](../avatar-research.md)，不重复下载第三方实现或角色。

## 风险

局部素材错位或颜色不一致会形成面部接缝，需逐表情和混合中间态截图检查。网格过大转向会拉伸脸部，需限制幅度。各端系统音色和语音事件差异很大，无法承诺所有 Android WebView/Electron/Linux 环境都有本地中文声；缺失时必须准确提示。排队重复播报、旧 utterance 回调、隐藏页面仍运行和资源泄漏是主要生命周期风险。测试模拟 voice/事件只能证明控制逻辑，不能替代实际听音。

## 验证计划

1. 运行针对性能辅助、朗读开关/分句/事件/停止/清理的有意义自动测试，并完成原有后端与行为回归及 TypeScript/Vite 构建。
2. 优先通过 Chrome 插件检查单角色画布、微表情渐变、休息/唤醒、双角色切换、低动态、桌面/手机布局、隐藏/恢复和控制台错误；区分文本口型、真实语音事件、估算与失败提示。
3. 朗读分别覆盖默认关闭、手动上一条、成功回复自动朗读、取消/切会话/隐藏/换猫停止；有本地中文音色的环境实际听音，没有音色的环境验证明确失败，不作成功宣称。
4. 冻结后分别重建 Windows、Android 与 Ubuntu 两架构，核对新增资源、实际版本和哈希；Windows 最终包检查透明小窗/真实CLI/退出回收。Android 与 Ubuntu 构建证据与目标设备运行证据继续分开。
5. 冻结后更新当前验收和源码归档，保留历史 0.2.0 事实；仅在本 issue 范围的必要检查完成后标记 done。

## 当前检查边界

源码已冻结，短回复状态批处理、休息朗读和语音 pending→active 的表情衔接均已修复；最终回归为 70/70，生产构建通过。Windows 源码和最终 EXE 均观察首页两句真实中文 TTS 的 2 start/15 boundary/2 end，停止、隐藏取消及 App 单块回复/休息保护通过；尚未人工听音或录音。Chrome 两次连接和一次恢复调用均超时，本轮 UI 依据 Electron 实测。Windows、Android 和 Ubuntu 两架构最终包已构建并核对对应资源；Android/Ubuntu 设备图形与声音验收仍未取得。源码归档 186 项成员回读与边界扫描通过，发布清单五个产物的哈希均与最终回执一致。
