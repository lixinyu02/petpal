# 深度流畅性优化

- Date: 2026-10-23
- Complexity: L2
- Baseline: main `a44330e`，开始时工作区干净
- Status: complete; measured outcomes and limits in validation report

## Background

用户明确要求设立goal并继续深度流畅性优化。上一轮已验证Android登录/权限/代理/renderer与原生前台恢复，但运行正确不等于滚动和流式渲染流畅。既有工作已做资源WebP、启动预取/压缩、隐藏轮询暂停及数据库省写，本轮先复核现有实现与记录，避免重复改动或把历史改善当成新收益。

## Goal

用可复现的合成工作负载定位启动、聊天滚动/流式输出、人物动作的主线程/绘制开销，优化真实热点，提供同条件前后数据、回归和独立Android QA包。覆盖共用前端，重点验证API36 412×960；保留各平台与真机验收边界。

## Non-goals

不重写框架/后端/数据库，不降画质或删动作掩盖开销，不调低模型/ASR/TTS质量，不使用生产账号/聊天或消耗真实上游额度做压力测试。不替换正式安装包、标签或升级清单，不动网络/代理/账号/信任配置。新包独立保留，线上同步仅在源码验证后按现有保全流程进行。

## Solution

1. 基线：静态热点审计与近期性能记录交叉核对，构建固定源码的隔离网页；合成长历史/持续小块流式回复/人物交互夹具，记录浏览器真实提交、长任务、帧间隔及布局/内存可观测指标。Android唯一owner复用精确任务AVD，真实打包页面采集启动与gfxinfo/JS指标；不用个人AVD。
2. 以证据选择最小热点集合：优先避免无关消息重渲染/重复富文本解析、流式事件引起的无效布局、隐藏/静止人物的无效工作。选定后更新本设计的具体策略与文件所有权，保持可见内容、工具状态、最终流式文本、滚动锁定、交互反馈与账号代际语义。只并行当前issue内互不冲突的文件。
3. 冻结最终资源并同条件重复测量。用真实组件测试覆盖调度/取消/迟到回调等语义；Node/TypeScript与相关Android运行回归。独立APK审计签名、源码/资源、CRC和私密内容，实际验证前台恢复等关键功能没有退化。
4. 必要的网页同步沿用assets先发布、HTML原子最后；逐项保全业务数据、旧资源、正式下载、信任和守护。无后端源码变化不重启后端。完成每个issue的自审和独立commit，再推送main。

## Impact

预期涉及共用React组件、流式更新/滚动调度或avatar渲染循环及验证夹具；实际产品变更范围由issue-1的测量确认，不预设大重构。Android打包和运行工具归单一owner，浏览器优先Chrome插件验收。

## Selected implementation after baseline

- 聊天：真实Chrome 1000条历史/100次更新中，reduced每轮100000次class清理和100000次属性清理。只清理本生命周期实际启用的动画节点；身份序列未变时不重复消费motion tracker。保持同层keyed rows，用最近一轮ReactElement缓存复用实际RowProps和Message引用均未变的元素。仍有必要的O(N)扫描，不声称虚拟列表。放弃Fragment分块：跨块重排会导致相同ID的OpenUI表单/焦点节点重新挂载。
- 人物：真实V12/Core的三轮固定指针负载为4358–4364次矩形读取/10秒，连续诊断dataset1510–1523次；无长任务。仅同一次pointer/refresh操作共享矩形，延迟tap/hold仍重新测量。连续诊断100ms发布，前两帧和语义变化立即发布，内部render/update保持30Hz配置。诊断帧计数采样有约3帧误差，不能当作精确显示FPS。暂不做transform投影、静态停帧、loader重排。
- 文件所有权：聊天与对应测试由login_frontend_audit负责；CubismScene/scene-loop与pet interaction/feedback及对应测试由login_backend_audit负责；Android测试夹具/Gradle/AVD仅android_permission_bridge；root负责集成、文档、验收和网页保全。
- Android基线APK f3765e0a…6d85和45原生/313网页资源逐SHA冻结，后续源码实现不影响该基线。Android test-only采集工具在最终issue-3完成运行验收后提交；不将未验证工具当产品修复。

## Risks

缓存可能掩盖对象原位变更或跨账号串数据；节流可能吞掉最终帧/回复/审批；滚动优化可能抢夺用户阅读位置；降低绘制频率可能影响口型/表情。所有候选须用相应语义测试和真实运行验证。性能数据受设备/温度/宿主负载影响，固定工作负载和条件重复至少3轮，报告分布与样本边界；不能把模拟器或算法微基准当真机FPS或生产SLA。

## Verification Plan

- 留存before原始样本和源码/资源摘要，再做after同条件对照；指标名、可用观察点、冷/热缓存及合成数据形状明确。
- Chrome操作真实组件/完整页面，Android API36真实打包页，必要时API33/35关键兼容回归；412×960、IME、深浅色与后台恢复保持。
- 流式最终文本/Markdown/OpenUI、用户主动滚动、历史切换/账号变更、取消和卸载等按实际变更覆盖。不开无关全量重复测试。
- 改善不稳定或来自工作负载差异时不宣称收益，保留失败与未改善样本；不为了漂亮数字削弱功能或门禁。
- 最终独立QA APK、保全/清理收据及验收报告；真实小米/荣耀与ARM运行仍单列未验证。
