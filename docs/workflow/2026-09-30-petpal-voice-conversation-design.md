# VibeVoice ASR 与伙伴语音对话

- Date: 2026-09-30
- Complexity: L2
- Status: updated

## Background

用户要求接入 `http://192.168.60.10:40000/`，二次元伙伴支持 ASR、LLM 和 CosyVoice TTS 连贯对话，适配流式并实际验证。现有 TTS 已支持 24 kHz PCM 流和声音驱动口型；ASR 只有配置占位。

上游实测为 VibeVoice Streaming ASR：`/ws/asr`，先发 options JSON，再发 24 kHz 单声道 float32 little-endian PCM，最后发文本 `end`。结果 text 为累计全文，done=true 才表示成功。约 2.93 秒推理块，单并发，最多 300 秒，忙时 1013。`/config` 与 `/healthz` 可探测。

## Goal

登录账号后在伙伴页主动开启语音聊天；识别字幕持续更新，说完自动提交，LLM 文本流按语句播放 CosyVoice，人物随真实声音动嘴；结束朗读后继续倾听。具备手动发送、打断、停止、错误恢复。延续 412×960 自适应。

## Non-goals

本轮不做唤醒词、后台永久监听、全双工回声消除或语音直接执行 Agent 命令；语音对话使用账号已授权的 Chat 模型，历史保存到同账号。暂不重制原生安装包。

## Solution

- ASR 由后端代理，前端不直连私网或持有服务密钥。管理员管理共享 VibeVoice 地址；用户主动开启对话即使用该服务。保留原 ASR 预备配置兼容性。
- 同源已鉴权 HTTP 会话桥接 upstream WebSocket：创建会话、顺序发送二进制 PCM 块、读取 SSE 累计字幕、结束与取消。每次请求验证账号及会话，限总音频/时长/帧大小/并发，错误不透传敏感配置。采用 ws 8.22.0 客户端，关闭压缩并限制握手、帧大小和关闭等待。真实服务对照中，Node 24 内置 WebSocket 在收尾时异常断开，而 ws 与 Python 均正常收到 done，故显式使用 ws。
- 浏览器 AudioWorklet 收音，使用所选麦克风、echoCancellation/noiseSuppression；重采样 24 kHz、有限样本检查、有界缓冲。VAD 配合短前滚和约 0.9 秒停顿划句，支持手动“说完了”。
- 状态顺序：idle → listening → recognizing → thinking/speaking → listening。TTS 期间停止发送麦克风音频，手动打断先取消 LLM/TTS 再回到倾听，避免扬声器自循环；最长单句/无声超时有界。
- 伙伴页增加简洁的语音聊天入口、状态、实时字幕、结束/打断按钮以及已授权模型选择。启动必须显式点击并获得麦克风权限；切换账号、页面隐藏、离开、设备丢失或错误时释放录音与请求。
- LLM 沿用现有 Chat SSE 和历史 API；回复按完整短句分段，CosyVoice 仍流式输出，保持单路播放、容量限制、取消和口型同步。避免同一回复重复朗读。
- 公网 Chrome 发现每 250 ms 一次串行上传无法承受 650–677 ms 请求往返；首块仍立即发送，在等待确认时动态合并后续 PCM，每包最多一秒，保持三秒未确认数据上限与逐帧确认语义。
- 用户在公网验收时追加 Markdown 显示要求。Chat/Agent 回复与伙伴语音字幕使用同一安全 Markdown/GFM 组件，禁原始 HTML 和危险链接协议；普通输入保留原文，复制仍提供原始 Markdown。朗读前移除格式标记，保持显示与语音各自适合的文本表示。

## Interface

视觉延续奶油白与浅绿、橘发伙伴，人物仍是首屏中心。语音入口位于底部，开启后以状态、模型、字幕和一个主操作替换原陪伴文案；服务管理保留在语音设置。倾听显示输入电平，回复随真实音频开合嘴型，状态切换保留人物与字幕位置，412×960 纵屏及窄高横屏均有专用布局。

## Impact

新增 ASR 服务/路由及公开配置类型、前端录音/对话状态机、伙伴 UI、语音设置。变更不扩大 Agent 权限，不暴露 ASR 公网端口。源码打包清单与原生 HTTP 桥接兼容需核对。

## Risks

上游单并发和约三秒识别块限制延迟，不能承诺逐字即时识别。浏览器硬件采样率、安卓 WebView 录音权限、HTTPS 混合内容、TTS 自动播放、无限队列和页面切换取消均须验证。生产部署必须完整备份，预期只新增管理员 ASR 配置；保留账号/模型/会话/参考声音。

## Verification Plan

单元/集成覆盖鉴权隔离、帧顺序/格式、忙状态、done/断线/取消、会话清理、采样率/VAD、语句切分与取消。真实服务用新合成中文测试音频验证上游流式识别，再经小伴完整 ASR→LLM→TTS 流测试，记录首段/最终时延及内容。Chrome 插件验收伙伴语音入口、字幕、口型、手动打断/停止、412×960 与桌面；合成音频注入必须标注，不冒充真人麦克风实测。通过后备份部署并公网鉴权/资源核验。
