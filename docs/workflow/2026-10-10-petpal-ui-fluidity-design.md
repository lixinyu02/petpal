# 小伴 UI 流畅性优化

- Date: 2026-10-10
- Complexity: L1
- Status: draft

## Background

基线为 main / 4f44f7b。既有 30 FPS 场景调度、隐藏暂停、消息引用复用、消息行 memo、50ms 展示合并及滚动合并继续保留。本轮只读审计发现 Cubism 的命中与区域计算各读取相同 canvas rect，悬停刷新重复写入稳定反馈样式；长流式 Markdown 每次展示都全文重解析，首页语音字幕逐 delta 发布并同步滚动。

## Goal

减少人物反馈的重复 DOM 工作和长回复的解析次数，同时保持首字即时、消息最终一致、真实语音口型和手势行为。

## Non-goals

不改变 ASR 检测、TTS 调度/口型频率、权限或模型接口。不引入消息虚拟化、重写渲染器、重打安装包或发布 GitHub。保留账号、聊天、后端数据与 dist/downloads。

## Solution

1. 为手势绑定提供可选的联合命中/区域采样，Cubism 单次操作共用一次坐标；每次仍读取当前几何，避免滚动、缩放、移动后热点失效。稳定反馈 dataset/style/cursor 避免写回。
2. 聊天展示累计 4000 字符后合并间隔为 100ms，8000 字符后为 120ms；短回复仍为 50ms，首字和协议事件 flush 立即。语音字幕复用同一展示器，但 TTS splitter 直接处理原始 delta；阶段结束、异常、取消有明确清理。首页字幕滚动改为单个 rAF。
3. 隔离后台任务面板，使稳定任务 props 不随语音进度反复渲染；不减少审批/状态通知频率。

## Impact

共享 Web UI 的 Windows、Ubuntu、Android 源码一并受益；本轮实际部署与验收仅本机网页。联合采样为可选接口，旧 3D/降级人物继续使用原接口。

## Risks

手势延迟验证不能复用过期坐标。反馈计时器不能被静止 refresh 重启。合并文本不能污染后续轮次、阻塞 TTS 首句或吞掉已接收文本。长回复最大展示延迟增加到 120ms，最终刷新立即。

## Verification Plan

运行手势/反馈、展示/语音取消及 Markdown 行为测试、TypeScript 和构建。以真实模块注入计数器比较 300 次悬停刷新 DOM 调用数、确定性长流的展示次数与解析字符量；Node 解析耗时仅作辅助。使用 Chrome 检查真实 Cubism 热点和 412×960 布局、隔离模拟流长聊天，记录证据边界。构建前后比较下载文件哈希。
