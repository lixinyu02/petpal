# 二次元表情与朗读联动

- Date: 2026-09-30
- Complexity: L2
- Status: implemented and web-verified

## Background

用户希望增加开心、伤心、难过、兴奋、害羞等表情，并探索与现有 CosyVoice TTS 结合。现有角色使用六张对位图像的 WebGL 网格混合与 DOM 降级；只有部分情绪关键词和微弱脸部通道，口型已支持实际 PCM 能量。

## Goal

同一人物有可辨别、平滑衔接的五种主要情绪。语音中按当前朗读语句选表情，声音能量只增强表演幅度；停止、缓冲、隐藏、减少动态和互动仍受现有生命周期约束。网页先上线，保留账号和原有配置。

## Non-goals

不更换人物、引入 UE/Cubism、不添加常驻表情按钮，不制作新安装包。文本规则不是人类情绪识别，PCM 能量不是情感或音素识别。上游未提供声音情绪参数时，不伪造 instruct 支持、不擅自更换音色或参考音频。

## Solution

- 视觉主张：温柔的奶油白／浅橘角色，以眼眉、脸颊、视线和姿态表达情绪，保留原有身份与构图。
- 内容安排：沿用伙伴页、Chat/Agent 旁边角色与语音字幕，不增加拥挤面板；验收演示只在本机测试入口提供。
- 动作主张：开心时柔和笑眼，兴奋时轻快点头与眼睛光泽，害羞时红晕与回避目光；难过为低落垂眼，伤心为明显内眉上扬和少量泪光，均缓动回归自然。
- 表演控制器新增 sad（伤心）、downcast（难过）、excited（兴奋），加强 happy/shy；提供 sadAmount、downcastAmount、excitedAmount、shyAmount、eyeSmile、tearAmount 等 0..1 通道。与嘴部发音通道分开，互动不覆盖负面语义成笑脸。
- 用同角色精准编辑生成 sad.png，只在局部眼眉/脸部采样。伤心与难过用同一对位素材的不同强度、眼神及姿态区分；高兴/兴奋/害羞复用现有对位资源，避免整张人物切换。
- 情绪按当前播放语句而非未播出的后文选择。对否定词、安慰语句和情绪枚举采用保守规则；播放时结合真实 PCM 的平滑能量，使点头强弱随语音改变，静音与缓冲不产生说话动作。
- 探测现有 TTS OpenAPI/Gradio 文档。只有明确支持且真实测试通过的情绪字段才加入请求；否则本轮交付表情、语音节奏及口型联动，保留原音色。

## Impact

影响 avatar 语义/表演模块、WebGL 与 DOM 渲染、表情资源、相关测试及文档。公共 API 和生产状态默认不变。静态资源隔离构建后备份部署，保留旧资源和已有服务。

## Risks

生成素材可能有眼位/面部色差，需要同尺寸、局部混合与截图检查。七张贴图不能超过移动 WebGL 采样器预算，DOM 必须保持可见。关键词会误判否定或引用，需覆盖实际边界；音频进度为估计而非严格音素对齐。表情不能抢占口型或放大音频。

## Verification Plan

纯函数测试五种情绪、否定/枚举/安慰、多句播放边界、PCM 发音独立、缓冲/停止/隐藏/reduced-motion和过渡范围。资源加载失败与DOM回退回归。TypeScript、隔离Vite构建及相关语音测试；Chrome桌面与412×960，按相同角色真实截图比较，真实CosyVoice流式联动至少一组。检查部署哈希、登录门禁及数据保持，提交并推送源码。

## Result

75 项相关测试、TypeScript 和隔离构建通过；五类短句均完成真实 CosyVoice 流式播放，并记录到对应表情、非零音频及嘴型，结束后闭嘴。网页已发布，14 项公网资源哈希与构建一致，6 个匿名语音入口仍为 401，生产状态与本轮开始前完整相同。详见同目录 `2026-09-30-petpal-emotion-voice-acceptance.md`。本轮未制作安装包；声音情绪语气仍为明确的后续能力边界。
