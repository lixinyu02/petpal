## 实际原因和保留边界

zut 的原申请已分配项目，Pod 的 agent/gateway 都是 Running、重启数 0，但节点记录仍 creating/revision10。实读容器 `/sys/fs/cgroup/pids.max` 为 18836，申请/平台固定限制为512，configz 的 podPidsLimit 虽为512，不能代替实际隔离证明。节点既有失败回执包含 kubernetes_pids_limit_unconfirmed。未放宽上限、修改宿主 cgroup、重启集群或把 Pod Running 当成平台就绪。

原 adapter 将 creating/recovery_required/unknown 都错误映射为 stopped，页面又把已知错误掩盖为未知送达。现保留真实阶段和创建错误；已明确的PID错误直接显示，未知回执仍保留原requestId。旧的15s冷启动限制和启动未携带原生revision也已补齐（120s有界等待、inspect后携带revision）。进入任务时已有这两份相关工作区修正，已先私有备份并审查，连同相应回归纳入本任务提交。
