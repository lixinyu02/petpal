## 实施与运行

通用 `petpal_browser` 支持任意合法 HTTP(S) 网站、端口和跨站跳转，不再限制为两个音乐官网。常用网站与固定查询适配器继续作为快捷入口，不限制通用网页工具的域名。保留账号、执行电脑、显式 Chrome 档案、审批、租约与取消语义，未迁移或覆盖关闭选择。

状态用 `websiteAccess=all` 声明实际能力。旧客户端不报告该字段时不显示通用网址入口；Windows/Ubuntu 已安装包需更新运行时才能获得本轮能力。

实际启动前检查 Codex 活动任务/审批均为 0、桌面工具不忙、状态文件无运行/排队/流式任务、4318 无在途连接，并核对进程与服务回执。生产构建明确不清空 dist；重启后健康 0.9.10、用户/会话身份、配对凭据以及全部 15 个下载文件的路径/长度/时间戳保持。

## Reconnecting 与导航修复

初始扩展 Reconnecting 时，本机 19825 浏览器桥未运行。通过小伴自己的连接入口启动官方 daemon 后，1.0.24 扩展连接成功。明确连接已观察到的 Chrome 档案后，真实服务返回 `ready=true`，不是 Chrome 验收插件代替小伴执行。桥重启时扩展有重连退避，不能将启动后第一秒尚未上线当成持续故障。

实测暴露 `tabs/new` 不保证导航就绪：新租约可能先返回空 URL 或 about:blank。现在只在本次新租约上有界等待初始导航，轮询只读列表，不重发打开。超时/取消保留精确租约，可单独关闭；已有页面变为非网页地址仍拒绝。

快照与所有有限操作同时绑定 href 和随机 document 标记；跨站、同地址重载、读取过程中跳转和失败快照均不能复用旧控件。页面刚加载/跳转时读取快照可能失败；实测重新观察同一租约并读取稳定页面可继续，不重复创建任务或打开页面。
