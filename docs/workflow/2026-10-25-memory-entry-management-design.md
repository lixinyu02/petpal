# 选择性管理已提炼记忆

- Date: 2026-10-25
- Complexity: L2
- Status: final

## Background

记忆设置只有只读预览和整库清空。需要在登录账号内查找、选择并删除部分已提炼条目。现有微信导入、模型配置与跨设备同步必须保留。

## Goal

提供按关键词搜索、分页、单条和多选删除。删除对象是 Memobase profile 条目，必须绑定当前账号和当前 epoch，确认时校验内容指纹。保留其余条目、聊天与原始档案。

## Non-goals

不替用户删除真实资料，不清空整库，不重建整库，不宣称会删除聊天原文或阻止未来新对话学习相似信息，不重打客户端。

## Solution

1. Memobase 客户端增加严格校验的 profile 列表和按账号/ID删除。服务端只接受当前会话的账号，不接受任意 userId。列表懒加载，限量分页；提交包含 epoch 和 ID/内容指纹，跨账号 ID 与过期快照拒绝。
2. 在现有私有记忆 journal 中保存不含正文的删除标记（ID、内容 hash、指纹、时间、清理状态）。先持久化标记并清除缓存，立即退出自动召回；正在提炼时等待 buffer 空闲，在同账号同步串行链上清理上游。处理前再次核对内容，不能删掉排队期间被修改的新内容。
3. 有删除标记的账号使用结构化 profile 重建召回文本，按 ID/内容 hash 排除已删除条目，避免旧 context 中的事件摘要、近期原话或缓存带回内容。此时原始历史档案仅供手动查阅，自动召回使用保留的提炼条目，界面明确说明。历史导入继续保存原事件和日期，不能重新 append 已有事件。
4. 中央下行快照带删除标记，PC 采用中央标记并清除旧缓存；本机备用提炼也过滤相同内容 hash。远程客户端的管理请求转发中央，离线时不伪报删除成功。旧客户端需更新共享后端后才具备该过滤机制。
5. 界面显示确认内容和条数，取消零写入，处理中禁用重复提交。删除清理排队时明确显示状态，失败不自动重发 UI 请求。

## Impact

新增账号内 GET /memory/entries 和 POST /memory/entries/delete。journal/下行快照增加可选字段，缺省为空，旧文件可读取；不改变现有 epoch、原事件、提炼模型和导入任务。

## Risks

上游没有条件 DELETE，必须在 buffer 空闲时核对新鲜指纹，保守保留发生变化的条目。离线设备在重新连接前无法获知新删除；接收删除标记后不得再使用旧全文缓存。原聊天和档案仍保存，新的明确对话可能学习新内容。删除只针对用户明确选择的提炼条目。

## Verification Plan

覆盖账号隔离、过期 epoch/指纹、批量原子准入、排队与持久化重启、缓存/备用/中央同步过滤、同 ID 幂等清理、故障与授权撤销。界面覆盖确认、取消、双击、换账号迟到响应、搜索分页、手机布局。只用合成条目做删除测试；正式账号只读验收。构建写私有候选目录，正式发布保留下载与业务数据，Chrome 验收。
