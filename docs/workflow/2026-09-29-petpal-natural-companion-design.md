# 自然角色交互与界面迭代

- Date: 2026-09-29
- Complexity: L2
- Status: final

## 背景与目标

用户希望继续优化隐藏问题、UI 与人物模型，去掉“摸摸头 / 喂零食 / 休息”等操作按钮，改成鼠标或触控直接互动。保留同一位奶油白浅橘二次元伙伴与橘白小猫、Chat / Agent、账号与模型权限、四端连接能力。

已有审查确认：工作台外层按钮与 Scene 重复处理点击；整个透明舞台吞掉手机滚动；睡眠状态可能与工作台文案分裂；猫的 0.85 秒行为与 1.35 秒模型跳跃不同步。另需检查执行器临时断网后恢复能力。

## 视觉与内容

- Visual thesis: 奶油纸色、森林绿操作色、柔和暖光，角色有自然呼吸和反馈，工作区减少边框与演示控件。
- Content plan: 首页只保留品牌、角色选择、角色本体、一句回应和聊天入口；工作台保留明确的模式/电脑/模型及输入区，右侧角色成为可直接互动的陪伴区。
- Interaction thesis: 角色接近视线、轻触时柔和回应、轻抚和长按有局部反馈；状态切换平滑，不重复创建角色；减少动态设置下保持操作有效。
- 不新增随机角色素材或重型引擎。先修正现有模型动作、人物形变和构图，保持用户已认可的角色身份。

## 交互协议

Scene 拥有唯一的 Pointer Events 入口，并向 React 通知交互和实际状态；移除外层可点击按钮及嵌套焦点。仅角色命中区域产生交互，舞台空白允许页面滚动。

轻触角色表示亲近/回应，双击或双触表示招呼，按住轻抚产生节制的亲近反馈，静止长按切换休息；睡眠时轻触唤醒。取消、失焦、离开页面、多点触控和滚动不能意外触发长按或留下指针状态。键盘 Enter / Space 提供等价操作，说明通过简短提示及可访问名称提供；不再呈现行为按钮。

共用可独立测试的手势判定，避免三套界面各自实现。React 回调不能重新发送同一动作形成循环。显示状态以 Scene 实际状态为准，语音在休息时停止。模型动画使用行为进度完成完整落地，接触反馈平滑衰减。

## 稳定性边界

用户追加鼠标小手与抚摸动画需求：仅在命中角色时显示小手，按住轻抚时跟随指针、角色自然回应；触控反馈短暂显示，空白滚动不受影响。减少动态设置下保留静态按压反馈，不加入持续摇摆或粒子。任务拆成 issue-29，在稳定性修复后完成再发布。

单独审查并修复可复现的执行电脑/账号/语音问题。网络恢复不能重放曾领取的任务或把未知运行当作已停止；账号和会话失效仍必须终止连接。所有已确认问题以回归场景覆盖，避免无边界重构。

## 验收与交付

按 issue 顺序实施。交互测试覆盖命中、单次触发、滚动取消、长按、键盘、睡眠唤醒；模型测试检查跳跃连续性和有限数值。Chrome 验收桌面及 412px 手机宽度下两种角色、触控/鼠标、工作台与首页，保存前后截图。执行相关测试、全量测试、TS/Vite、公开源码审计。

构建到独立目录，避免覆盖正在服务的 dist。备份后部署且保留账号/模型/语音/历史。新版四端包版本一致，验证后签署递增更新清单并发布；Windows 实际运行验收，Ubuntu/Android 未有目标实机时明确报告边界。所有私有数据和发布凭据仍留在忽略目录。
