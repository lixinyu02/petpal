# 语音聊天环境噪声误触发修复

- Date: 2026-10-09
- Complexity: L1
- Status: draft

## Background

普通监听使用固定 RMS 0.014 且无需持续确认，单个 250ms 音频块即可创建 ASR 会话。麦克风自动增益会抬高环境声；打断检测虽然已有持续门槛，仍不适应底噪。

## Goal

默认降低环境噪声和远处人声误触发，保留词头、900ms 停顿提交、持续说话打断和已有账号/设备隔离。

## Non-goals

不替换 ASR 服务、不训练声纹、不重打客户端。能量检测不能可靠区分音量相近的旁人/电视人声与本人讲话。

## Solution

1. 保留 24kHz/250ms 上行格式，在门控内部以 20ms 小段检测，防止瞬态噪声抬高整块 RMS。起音需持续确认并允许短音节间隙，200ms pre-roll 和确认期音频有界保留。
2. 提高默认起音门槛，根据未说话时的低电平底噪平滑提高门槛；候选讲话、实际讲话和 TTS 播放时不学习为底噪。续音使用较低门槛，监听切换不清空底噪，打断共享监听底噪且门槛更严格。
3. 麦克风关闭自动增益，保留回声消除和降噪。新增本机、当前账号的「抗干扰 / 均衡 / 灵敏」选择，默认抗干扰；设置变更终止旧收音，下次开始读取。

## Impact

仅影响前端麦克风采集和语音聊天门控。服务协议、用户账号、聊天、下载文件不变。

## Risks

关闭增益及更严格起音可能要求低增益麦克风靠近说话，可切换均衡或灵敏。底噪检测不等同神经网络 VAD / 说话人识别；仍需用户现场环境确认。

## Verification Plan

测试持续底噪、短脉冲、底噪变化、正常短句/轻声续音、重置后底噪保持、原采样率重采样、起音完整性、回声和打断、账号隔离/坏存储/设置读取；运行语音链回归及 TypeScript。保留 dist/downloads 构建，本机 Chrome 验收设置与健康。无真实用户现场声学验收时明确边界。
