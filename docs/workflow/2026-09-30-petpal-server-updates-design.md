# 服务器直接发布更新

- Date: 2026-09-30
- Complexity: L2
- Status: complete (2026-10-01)

## Background

用户希望除 GitHub Releases 外，也可以直接从自己的服务器提供更新。现有四端更新检查、清单签名和原生下载仅允许 GitHub。用户选择本轮先上线网页与后端，之后再打包客户端。

## Goal

软件内可选择 GitHub 或服务器来源；服务器提供签名清单与实际文件，四端沿用现有校验及安装交接。上线可访问的服务器更新源，保留旧 GitHub 配置和已有下载。

## Non-goals

本轮不重新构建安装包，不自动推送安装、不做无提示后台安装，不自动在来源间切换，不将历史二进制标为含本轮新功能。

## Solution

更新配置新增 source（github/server）与 manifestUrl。旧配置缺少 source 时按 github 处理；保留 repository/publicKey/revision。服务器清单须为无凭据、查询、片段的 HTTPS URL，允许已使用的44318端口。其资产与受限重定向须在清单同 origin、同目录范围内；拒绝编码穿越、点段及跨源请求。不携带个人服务 Bearer/Cookie。

签名仍为 Ed25519 envelope，先验签再解析；保持清单大小、有效期、稳定版本、平台格式、文件长度、SHA256校验及公钥指纹+通道的最高sequence记录。换源改变revision、取消旧检查并使旧下载失效；同公钥切换源不清空防回滚记录。重新签名服务器URL必须采用更高sequence。

正式服务器使用独立的发布密钥；GitHub 原密钥保留。两者资产URL与签名payload不同，若共用公钥，两个独立feed必须共用全局序号，否则会互相触发降序或同序不同内容拒绝。生产选择独立身份，切源须填写该来源对应的公钥；不同公钥独立保存最高序号，切回旧身份仍保留其防回退记录。服务器当前sequence=7，文档发布示例使用下一序号8，不把两目标示例当作当前五目标清单。

共用设置页提供来源选择、仓库或清单地址和发布公钥。Desktop在检查、下载、缓存、安装前复核及最终启动前绑定来源与清单；Android保留旧GitHub策略并在实际下载与安装前复核中带上新绑定，保持包名/签名/versionCode要求。签名发布工具从真实文件自动生成服务器同目录资产地址，不接受任意URL/摘要。

正式服务器静态目录发布清单及现有已验证安装包副本，新Web ZIP只表示本轮网页资源。生产管理API配置服务器来源；账号鉴权、历史、语音、暂停队列和旧下载保留。原生代码准备完成不等于旧安装包已具备新来源选择。

## Impact

server更新源策略、共用设置页、发布工具、Electron/Android下载策略和对应测试。与聊天、Agent权限、模型和语音协议无业务变更。

## Risks

URL规范化和重定向可能绕过目录限制；恶意或过期清单、降序sequence、下载变化与切源竞争必须失败关闭。生产发布需要保持旧HTML/hash资源可回退，并区分源码能力和已发包能力。

## Verification Plan
