## 已实现

登录后在伙伴页点击“语音聊天”，使用当前账号授权的 Chat 模型和所选麦克风/扬声器。AudioWorklet 将输入转换为 24 kHz 单声道 Float32；VAD 在停顿约 900 ms 后结束一句，也可手动发送。ASR 累计字幕持续替换，最终结果发送给聊天模型，回复按语句调用 CosyVoice 流式播放，人物按实际 PCM 音量调整口型。

播放时关闭麦克风轨道，回复结束后重新倾听；支持打断、结束、静默 45 秒退出。离开页面、切换账号和设备丢失会清理资源。共享 ASR 地址仅管理员可改；识别会话绑定创建时的登录，不可由另一登录接管。ASR/TTS 都有并发、时长、容量和取消边界。

## 实测发现与修正

Node 24 内置 WebSocket 在上游发送最终结果时异常关闭，Python 与 `ws 8.22.0` 对照均正常。因此后端显式使用 ws、关闭压缩，并增加握手、帧大小和关闭超时限制。

公网 Chrome 曾出现单次音频上传 650–677 ms，而采集每 250 ms 发一块，导致串行请求积压。现已在等待 ACK 时合并后续音频，每包最多一秒，仍保留三秒未确认音频上限。模拟上述延迟连续 45 秒 / 180 帧测试验证无丢样、重排或并发上传，之后公网完整闭环通过。

人物 PNG 曾瞬时超时；页面重试后恢复，独立 HTTP 检查确认 PNG 状态、长度与 SHA-256 完整，未修改图片或缓存策略。

用户指出回复中的 Markdown 未解析，随本轮补齐共享的 Markdown/GFM 展示：Chat、Agent 和伙伴语音字幕支持标题、强调、列表、引用、代码、链接及表格。代码和表格在窄屏内局部滚动，禁原始 HTML 与危险链接协议，Markdown 图片仅显示替代文本，不自动请求第三方图片。

最终公网 Chrome 验收中，已有回复的 `**5**` 成为 `<strong>5</strong>`；点击消息旁朗读及连续语音的实际 `/api/voice/synthesize/stream` 请求均为“二加三等于 5。”。Agent 原有回复渲染出列表和 6 处行内代码，三个入口均无横向溢出。流式分句保护强调、链接、代码边界；代码提取后不二次解析，保留 `10**2`、`some__key` 等字面内容。

最终合成音频复验依次经过 listening → recognizing → thinking → speaking → listening，人物开口采样最高 0.584；45 秒静默后自动结束，麦克风轨道为 0。字幕显示粗体 5，朗读没有星号。Chrome 的单次等待注册较晚，最终超时返回 idle；全过程的 80 ms DOM 采样记录确认上述完整顺序，不以等待超时作为语音失败。

## 部署与数据

部署前发现原后端与既有 HTTPS 隧道监督进程已退出，公网返回 502；日志没有记录退出根因。已备份原前端、原服务源码、配置和状态，启动验证过的新后端，恢复既有隧道。HTTPS 证书默认校验通过；公开 HTML/入口 JS/CSS 的 SHA-256 与构建一致。

新后端启动时旧状态完整比较通过：2 个账号、16 个原会话、模型、Agent 配置、附件及参考 WAV 保持。随后通过管理员接口仅新增共享 ASR 配置。公网验收的登录/注销按既有会话上限规则淘汰最旧 test 登录；Chrome 两轮完整验收新增 2 条合成问题会话，总数为 18。最终只读审计确认原 16 条逐项完全相同、账号和模型等其余配置保持、参考 WAV 长度与哈希相同，test 的临时二次元角色选择已恢复原来的小猫。预期差异仅为 ASR 配置、测试新增会话和登录会话状态。

后续前端修正使用先复制内容哈希资源、最后原子替换 HTML 的方式，保留旧资源供已经打开的页面使用，不重启后端。备份、凭据和含运行态的原始证据均只留本机忽略目录，不提交公开仓库。
