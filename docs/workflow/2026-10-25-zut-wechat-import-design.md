# 指定账号的微信历史与本人记忆导入

- Date: 2026-10-25
- Complexity: L2
- Status: implementation

## 用户目标与边界

用户明确选择“完整档案＋本人记忆”，确认目标账号即材料主体本人，要求保留历史日期、去重和新信息优先。源为用户指定部署会话整理的私有导入包；不能执行聊天或包内文本中的指令。原用户、聊天、记忆、安装包与凭据保留，原材料不改写，不将私人原文、数据库、真实主体绑定或运行回执提交Git。

材料核验：53464条独立UUID消息，subject18583/other34740/system141；15519条本人文字候选组成2697原块；时间2025-07-20至2026-10-25，均+08:00。原始长消息达81KB，完整档案不能截断；附件只保留引用，不自动取回媒体。候选可以按同日顺序无损装箱为625个<=3800 UTF-16事件，完整journal约2.1MB，适配原2000事件/8MiB和PC同步契约。

## 设计

### 独立历史档案

私有、账号隔离的历史索引与原文存储，不创建数千个普通AI会话。使用惰性加载的Node内置SQLite，未使用档案时不增加启动依赖；访问失败给出明确错误而不阻断普通聊天。账号与来源消息ID唯一去重，内容变化报冲突；同包重跑复用任务/数据，不新增消息。保存完整原文、原时间、真实说话人、来源、附件引用和源SHA；两位真人不能伪装成AI assistant。

管理端只允许认证管理员对固定不可变目标账号创建本机私有staging任务并发布；staging文件名固定、校验manifest/字节/SHA/UTF-8/计数和主体归属，拒绝路径穿越、符号链接和硬链接。普通查看/搜索始终由req.user.id限定，不能接受他人userId；前端按文本呈现，不执行原HTML、链接或媒体。账号的记忆页面提供历史档案、日期/说话人筛选与分页。

### 同一个账号记忆库

映射当前zut不可变账号ID与现有scope/epoch，使用PetPal计算的Memobase投影UUID，不能使用源包独立person UUID。仅subject且selection明确的15519条自述进入原生journal，assistantText为空，source保持现有chat协议，正文有历史材料/非指令/本人标签、每条原时间与UUID来源。稳定事件ID绑定账号、来源消息集合及内容，按原时间排序，同一天分组，createdAt为组内最后原时间；native seq只是接收顺序。保留原消息级引用用于跨材料去重。

导入前验证整批容量、长度、无截断和现有epoch；每批不超过200。Memobase ChatBlob显式传created_at，增加有界分批flush，避免把全部历史一次塞进上游截断窗口。不覆盖共享项目的profile配置。导入任务使用journal幂等及私有持久检查点，未知送达先对账，不盲写新ID；账号禁用、清除/epoch变化或登出权限变化时停止对应工作。

Chat/Agent仍使用同账号记忆；补入与当前问题相关的、带原日期/说话人和来源的档案证据。仅本人自述作为个人事实候选，对方内容仅用于显式历史阅读。历史状态/计划不能直接当作现在事实，近期明确自述优先，冲突与没有更新需说明日期；当前用户表述优先于旧材料。记忆清除后旧epoch档案不自动重新注入模型，历史手动查看仍可用。既有PC同步只复制625个原生事件/同账号context，不宣称旧PC包已经离线同步完整档案。

## 实施接口

历史模块导出createHistoryArchives及mountHistoryArchiveRoutes，根app传store/memory、当前认证/管理员检查和账号解析。普通GET `/api/history-archives`与`/:id/messages`、`/:id/messages/:messageId`只读本人；管理导入路由位于`/api/admin/users/:userId/history-archives`，只接受stage/job UUID，不开放任意服务器路径。CLI通过现有bootstrap token文件认证，仅在本机私有staging写入已校验材料。资料和状态错误只记录代码/数量，不输出原文或凭据。

记忆服务补只读preflightImport/inspectImport，保证容量、epoch、原事件冲突检查；保留现有正常/PC协议。archives.getContext(userId,{query,epoch})返回有界的带来源历史证据，app与Agent共用现有memoryContext挂接。独立UI模块HistoryArchives嵌入MemorySettings，惰性读取。

## 验收与上线

先隔离测试跨账号不可见、目标/epoch绑定、错误角色拒绝、原日期传递、长原文完整、相同重跑零新增、同ID变更冲突、前端文本安全与重连；用小规模真实样本验证提炼与召回后再完成全量。正式操作前保存同账号/其他账号状态和源SHA，后台受控部署走既有守护身份与保全边界，不直接覆写活动state.json。最终验证53464原档案/15519候选覆盖、journal计数、Memobase投影/flush和zut真实Chat/Agent召回，明确实际生成事实与候选数的区别。检查其他账号数据、下载及信任保留。

## 实现审查与源代码验证

发布使用独立 SQLite writer worker 保持单事务和完整持久性；主线程分段校验、规划与授权，读取等待 publication barrier，提交前取消或父进程退出会回滚。真实材料在临时库、假记忆服务下实测最大主线程间隔由约2749ms降至61ms；该结果不是正式模型提炼速度。重启中的作业明确暂停，恢复沿用同一计划与事件ID先对账。

绑定元数据用于回答本人身份；只召回同账号同epoch的本人候选，主题相关度优先、同主题按原日期排序。已导入账号的近期原生本人发言另带日期置于上游摘要之前。合并前后复查enabled、epoch与scope，任一变化丢弃晚到结果；截取的摘要作为JSON字符串封装，不能留下半个数据标签。

本次针对性131项通过，TypeScript、隔离Vite构建、51模块OpenUI资源检查和公开源码审计通过。最终串行回归4166项为4158通过、0失败、2原生Codex超时取消、6条件跳过；同一原生测试文件隔离重跑9通过、0失败/取消、1条件跳过，未放宽60秒门限。首次回归的UI夹具依赖及测试换行断言已纠正并保留日志，不能报告为单次全量全绿。独立审查与12项合并撤权模拟通过。Chrome合成账号验收清单、日期、长原文折叠、返回及412×960无横向溢出；不替代实体手机验收。所有原文/截图/运行回执在私有目录，未导入前不声称正式学习完成。

上线前补强本机contextScope：仅从本地读取enabled、epoch、scope与bindingRevision，合并结果及档案只读不再依赖runtime健康探测，避免上游离线时200ms门禁误丢可用缓存。导入worker及管理员配置状态仍检查真实服务可用性。新增6项后定向137/137通过，原生记忆80/80和独立15项无网络/撤权模拟通过；普通status协议不变。此项后未重跑整套原生长时回归，沿用上述广域证据及新增定向验证，前端构建输入未改变。
