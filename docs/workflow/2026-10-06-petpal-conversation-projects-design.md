# 对话管理与项目分类

- Date: 2026-10-06
- Complexity: L2
- Status: final

## Background

目前侧栏只有最近对话与删除入口；Chat、Agent 和后台派发的任务共用用户隔离的 JSON 存储。新增分类必须保留任务回执、图片与模型配置，不让后台保存覆盖用户的整理结果。

## Goal

为 Chat 和 Agent 提供重命名、归档/恢复、确认删除及按项目分类。项目是账号内的对话分组，新对话继承当前项目。所有界面共用这些能力。

## Non-goals

项目分类不改变 Agent 的执行电脑、工作目录或权限；不引入文件系统项目。此轮先更新网页/后端源码，不重打 0.9.9 安装包或修改更新清单。

## Solution

- 项目记录：`id/userId/name/createdAt/updatedAt`，每账号最多 50 项、名称去空白后 1–60 字符。API `POST /api/projects`、`PATCH /api/projects/:id`、`DELETE /api/projects/:id`；state 只暴露当前账号的项目且不暴露 userId。删除项目把对话移到未分类，保留归档与记录。
- 对话新增 `projectId: string|null`、`archivedAt: string|null`、`customTitle?: string`；对外 title 使用 customTitle 优先于自动摘要标题，避免后续消息覆盖手动命名。旧数据迁移为未分类/未归档。
- `PATCH /api/conversations/:id/organization` 接受 `title`（1–100 字符）、`projectId`（本人项目或 null）、`archived`（boolean），返回完整可见对话。此路由不切换模型，不影响后台执行；既有 providerId PATCH 保持。
- 归档只是收纳，任务继续执行，归档区仍能查看回执/恢复/删除。后台子任务由父 Chat 管理，不独立分类。
- 删除仍需明确确认；后台子任务、前台流式回复、正在运行/停止/未知状态的 Agent、有排队任务或尚未结束的 Chat 派发任务拒绝删除并提示先停止。删除空闲父会话同时清理其子任务记录。避免并发新提交在等待保存期间被误删。
- JSON 存储在串行原子保存队列中合并已提交的项目/分类状态；只在落盘成功后发布整理结果，写失败不让 UI 或内存残留半更新。显式操作需在执行队列内重新检查登录、归属、引用与忙碌状态。防止旧快照复活删除项目、回滚归档和标题。
- 侧栏紧凑项目选择、全部/未分类/具体项目，当前/归档视图，项目新增/重命名/删除及对话更多菜单（重命名、移动、归档/恢复、删除）。显示分类计数；不呈现聊天正文。弹窗支持键盘、焦点、失败重试，手机触屏直接可点。
- 选中对话归档后继续保留当前正文及草稿；恢复到所属分类，创建新对话时当前归档视图切回当前。删除选中对话先验证草稿保护、停止播放，成功后清理选择与缓存，避免残留失效 SSE/任务轮询。

## Impact

server/store/app、api types、App 导航与创建入口、ConversationHistory 和独立样式、HTTP/store/渲染测试。保持账号 epoch、防重复 Agent 提交、低成本侧栏 memo 和移动端导航焦点边界。

## Risks

- 后台任务与分类保存并发，需合并持久化元数据而非替换整个对话。
- 归档任务完成仍应通知并可恢复；不要用 archive 隐藏账号授权或任务状态。
- 项目删除及持久化失败必须保持聊天正文、图片、Agent 目录和模型不变。
- 浏览器操作仅使用 Chrome 插件；公开服务重启前确认用户任务空闲。

## Verification Plan

HTTP 账号隔离、字段校验、Chat/Agent 生命周期、忙碌删除、旧版迁移、重载、并发快照与失败恢复；组件 memo/无正文泄漏/可访问操作测试；相关前端导航和任务回归，TypeScript/Vite 构建。Chrome 实测新建项目、重命名、移动、归档/恢复、删除项目保留对话、删除确认、刷新持久性及 412×960 无横向溢出。上线前备份、只替换后端/网页并保留客户端下载和更新清单，公网 health/index 验证。
