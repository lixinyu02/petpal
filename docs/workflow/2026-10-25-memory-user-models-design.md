# 用户记忆提炼模型与并发

- Date: 2026-10-25
- Complexity: L2

每个账号可在管理员已授权的 API 模型中选择自己的提炼模型，以及 1–3 路模型请求并发。默认继承中央模型。账号仅提交 providerId，不接触其他用户配置或密钥；模型失效/权限撤销应明确阻断，不静默改用其他模型。

Memobase 0.0.42 的全局模型配置不能直接表达每用户模型，并明确提示并行 flush 可能重复。保留同账号、原日期的事件顺序与原生归属，只在其既有独立 LLM 分支中允许最多 3 路并发。不同账号继续隔离。用小型 Python 启动适配器为 BLOBS_PROCESS 设置 ContextVar，并在 LLM factory 上选择账号路由与 semaphore，不修改上游数据库和画像合并实现。

私有配置分为仅保存 providerId/并发的偏好，及只读挂载到 Memobase 的机器路由文件。投影前解析实时用户权限和 epoch，只有当前映射的 Memobase UUID 可提炼；过时/撤销映射拒绝。用户切换模型在下一次完整 blob 提炼生效，同一次提炼固定模型快照。运行时文件不进仓库。Python 适配器与既有来源/许可声明一起校验哈希。

用户指定 zut 使用 Halogen 的 Qwen。切换前让当前历史批次收敛并保存热备份，再加载后端/运行时适配，核对缓冲和已确认的源事件 ID，继续原任务。其他账号不被改写偏好。实测包括账号/权限/epoch 隔离、模型失败无静默回退、3 路峰值、同账号顺序与原始时间、真实 Qwen 提炼和网页选择。
