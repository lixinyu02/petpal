# Android 长期登录与恢复

- Date: 2026-10-23
- Complexity: L2
- Status: updated

## Background

Android已用Keystore/AES-GCM和AtomicFile保存会话，冷启动优先恢复；当前后端会话却固定7天，且无续期。通用API的401会直接清登录；保存登录但暂时验证失败时仍出现完整登录表单。Agent与Chat+Agent引用sessionHash，长寿命setTimeout还存在2^31-1溢出耦合。

## Goal

Android显式默认记住设备：90天闲置有效，前台验证成功后按天滑动，365天绝对上限；现有有效会话可升级，过期/撤销不能复活。断网只显示重连，恢复网络/前台自动重试；原生临时读取失败可显式重试，不存密码、不绕过服务器身份验证。

## Non-goals

不做永久不失效token，不恢复已撤销/过期会话，不自动重新输入密码，不取消管理员撤销；不改普通Web默认7天、后台通知凭据寿命或安卓加密vault格式。保留账号、聊天、代理、正式下载与签名。Keystore损坏重建和原生锁架构另行处理。

## Solution

1. login请求可显式rememberDevice=true。Android客户端在登录及GET auth/me添加长期登录偏好；服务端仅对已认证的当前会话应用，保持原token与hash。新增90天idle/365天absolute常量，独立于普通7天SESSION_LIFETIME。持久化每日最多一次，续期不改变createdAt或其他session身份；有效旧会话首次成功验证可升级。按最近验证时间有界淘汰会话，避免简单按创建顺序踢掉活跃设备。
2. auth/me返回当前会话到期元数据。登录失效使用明确session_invalid码；通用业务401由客户端在同epoch单飞验证auth/me后才清登录，支持旧服务端，网络不确定则保留登录。登出、改密、禁用、权限撤销与续期并发必须保持撤销优先，保存失败不能发布成功续期。
3. Agent与Chat+Agent会话截止计时改为有界分段重新授权：不把90天直接传入setTimeout，分段到期重新读取当前有效期，清理时能取消计时，续期后不按旧截止误停。默认7天通知凭据不变。
4. 保留现有原生epoch/加密写入交易；暴露单飞retrySavedLogin，临时vault读取失败不清文件，显式重试成功后再验证。LoginGate保存token但离线时显示独立重连视图；online/focus/visibility恢复去抖重试，不后台轮询、不抢新账号。明确切换账号才显示登录表单，真正失效仍要求登录。

## Impact

后端会话策略与计时器、前端API与登录入口、Android安装包；普通Web保持原默认寿命。长期登录为已授权账号的设备偏好，不授予新权限。部署需保护业务状态和正式下载。

## Risks

期限变长增加设备凭据寿命，依靠原生加密保存、绝对上限和即时撤销约束。原token续期不能复活被删除的对象；磁盘写失败、并发验证/注销必须有范围与保存次序门禁。恢复事件和401确认必须隔离账号/服务/epoch、去重、允许取消；未验证成功不得展示私有内容。只模拟时间推进，不修改系统时钟。

## Verification Plan

Node fake-clock覆盖7天后/90天idle/365天absolute、每日写盘、重启、撤销/保存失败、计时器超长/续期。前端真实组件处理器回归网络恢复、401并发、冷启动和迟到结果。Android原生/应用进程重启与加密存储回归，独立QA APK完整审计；后端/网页部署后健康与状态保护检查。物理OEM机未连接则明确边界，不覆盖正式发布清单。
