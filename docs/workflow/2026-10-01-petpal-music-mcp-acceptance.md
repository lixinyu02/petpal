# 桌面音乐 MCP 验收

## 交付范围

本轮实现 issue-60 的 Windows／Ubuntu 客户端源码、后端接口、账号与执行电脑隔离、音乐 MCP 设置及打包清单。网页和后端按用户既定顺序先上线；既有 Windows／Ubuntu 下载包保持原样，新版安装包尚未制作，不具有本轮新增的本机 IPC 能力。

两项目以固定 commit 和原始 MIT 许可随源码保存，生产 Node MCP SDK 固定为 1.31.0。Python 由用户在执行电脑安装；准备入口安装固定版本依赖，登录凭据位于当前服务账号的本机私人目录，不进入 Git、客户端包或接口响应。

## 当前证据

- 真实 Windows Python + MCP SDK：网易云实际发现 14 项允许的工具，状态读取成功；QQ 实际发现 9 项工具，搜索、歌曲详情和歌词查询成功。未登录时获取播放地址明确失败，并保持 `playbackStarted=false`。
- Windows Electron 源码启动：真实执行器登录、注册在线，Codex／OpenCLI 可用，音乐 MCP 原生桥可用，默认关闭。此证据不是新版 exe 的首次安装验收。
- 原生设置、中央会话账号 scope、所选电脑转发、完整访问、询问审批、自动运行、停止、注销与降权边界均有回归；独立自审修复了取消请求最终状态返回的注销竞态。
- Linux 打包源清单与校验器覆盖 12 项固定 vendor 文件及哈希、manager/routes、SDK 生产依赖，拒绝缺失、篡改文件和意外凭据；补齐原有启动诊断模块遗漏。
- TypeScript、独立 Vite 生产构建和 Chrome 412×960 CSS 界面验收通过，音乐 MCP 区域无横向溢出；运行环境、来源及工具清单折叠显示。
- 最终全套测试 1035/1035 通过（38.3 秒），音乐 manager 定向 37/37；测试期间最终 manager 和测试文件指纹保持一致。生产 Codex transport 未改，测试夹具避开 Node fetch 禁止的端口，并等待真实响应建立后再验证取消。

原始协议、manager 调用、源码原生 smoke、构建、测试、Chrome 截图和私有部署回执保存于被 Git 忽略的 `evidence/music-mcp-20261001/`，不提交账号状态、运行路径、凭据或诊断日志。

## 能力边界

| 功能 | 已实现接口 | 实际验收边界 |
| --- | --- | --- |
| 网易云搜索、播放指定歌曲、队列、循环、音量、桌面歌词 | 固定 Windows 上游 14 项工具 | 工具发现及状态已实测；当前安装 3.0.9.202664，上游仅报告实测 3.1.24.204791，高级 webpack/CDP 控制与真实播放尚未验收 |
| 播放、暂停、上一首、下一首 | 现有指定播放器的 GSMTC／MPRIS 工具 | 不使用全局媒体热键；本轮未实际改变用户播放器状态 |
| Ubuntu 网易云高级接口 | 显示上游平台限制 | 不声称 Windows-only 上游已经适配 Linux；保留 MPRIS 能力 |
| QQ 搜索、详情、歌词、推荐、排行榜、地址 | 9 项真实 stdio 工具；排行榜为 `detail(type="top")` | 搜索、详情、歌词已实测；QQ 凭据与会员权限由上游判定，未扫码登录或验证授权地址 |
| QQ 桌面播放指定链接 | 不属于指定上游能力 | 返回链接不代表桌面播放；不能用查询成功代替播放成功 |
| Chat／Agent 远程使用 | 使用选中且当前账号登录的 PC 执行器 | 路由与审批回归通过；没有用真实外部模型派发一次音乐播放任务 |

新工具版本为 `music-mcp-v2`。历史记录保留，旧 Agent 对话需新建对话才能使用新工具；默认未开启音乐 MCP，也不会在刷新或连接测试时启动音乐软件。
