# 按对话独立运行并允许自由切换

- Date: 2026-10-25
- Complexity: L2
- Status: final

## Background

当前 App 只有一个 Chat AbortController、恢复请求和全局 busy 状态，导航在 Chat 或 Agent 运行时被拒绝。新发送会使旧 requestSequence 失效，因此只放开按钮会丢失旧回复。用户要求参照 Codex Remote，在发送后切换其他线程；提供的 Codex 聊天仅作为后台任务交互参考，不把 Sirchmunk 的服务取消逻辑移入小伴。

## Goal

已发送的 Chat 按对话独立流式运行，A 运行时可以进入 B/新对话并发送，切回 A 保留进度。Agent 已受理的任务允许切换，回到原对话仍使用既有任务读取。停止、恢复、错误和附件清理仅影响所属对话；后台回复不抢占选中项、草稿、语音和人物动作。侧栏标识运行与未读完成。

## Non-goals

不修改模型 API、服务端断线取消策略或 Agent 执行权限；不承诺浏览器刷新/关闭后 Chat 继续生成；不改变未发送草稿/图片的离开确认；不重打客户端或重启后端、记忆容器。

## Solution

1. 增加账号生命周期内的 Chat 运行注册表：按 conversationId 归属 controller/display/recovery/clientRequestId。新建对话在 ID 确认前使用临时槽位，这段短暂准入期间仍阻止切换。同一对话不能重复生成，不同对话互不使旧请求失效。再次发送同一对话会废弃上一轮迟到恢复。
2. 运行所有权与前台可见性分开校验。所有消息写回原对话，并在 React updater 内再次检查账号/运行/删除屏障；状态、错误、自动朗读和人物表现仅投影到当前对话。切换不会 abort、关闭 display 或取消其他对话的 recovery。
3. 发送时将图片/正文交给本次运行并立即清理原输入框；迟到 meta 不再清空新对话附件。失败草稿仅可恢复到原对话，不能进入另一对话。停止保留 expectedRequestId 保护，不触碰后台其他运行。
4. 导航只保留准入、模型切换、未知 Agent 提交和自动化保存保护。Chat/Agent 已运行本身不挡对话/页面切换。回到独立首页会卸载 App，存在 Chat 运行时保留提示，避免误断开流。
5. 普通全量状态刷新保留仍运行的 Chat 消息，不覆盖增量；运行终态仍由对应 stream/recovery 的权威快照更新。侧栏活动只在启动/终态/阅读等变化时更新，不订阅逐字进度。
6. App 卸载/账号切换关闭全部本页运行，迟到帧不能污染下一个账号；已删除对话不能由恢复结果重建。保持服务端现有账号、审批与删除 ACL。

## Impact

共享前端、Chat 生命周期辅助模块、状态合并和侧栏。无需数据库或 HTTP 协议迁移；Web/Android/Windows/Ubuntu 共用源码，当前先上线网页。

## Risks

重点防止 B 发送让 A 丢回复、A 终态释放 B 的锁、迟到 meta 清 B 图片、背景错误/朗读打扰 B、过期 GET 覆盖增量，以及停止错线程。单例 Agent 未知提交仍保留保护。浏览器刷新/关闭属于既有断线行为，不伪报后台持久生成。

## Verification Plan

注册表与合并单元测试；执行真实 App send/stop/navigation 函数的交错流测试，覆盖 A/B 并发、切回、恢复、停止、账号切换、删除和附件/语音隔离；既有 Chat/Agent/侧栏/语音回归、类型检查与候选构建。用隔离的慢速模型和 Chrome 验证实际操作，正式站只读；HTML-last 发布且不改业务数据、记忆或下载。
