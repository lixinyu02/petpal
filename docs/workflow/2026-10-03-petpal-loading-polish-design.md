# 角色加载与模型选择优化

- Date: 2026-10-03
- Complexity: L1
- Scope: Web/源码；减少角色成功加载路径开销，改善触控模型选择，不改人物资产或已发布客户端包。

## 设计

视觉方向：保留温柔的奶油白与浅橘人物，加载期使用同一人物的静态底图，避免两套动画抢占资源与突变。内容保持人物、简短状态、现有操作入口，不增加常驻技术标签。交互保持原生表情与抚摸动作，准备完成后平稳显示；触控先展示模型选项，键盘打开仍定位搜索，小屏弹层关闭按钮提供 44px 点击范围。

原生 Cubism 成功时不启动备用 Three.js 网格，不加载备用表情集；失败时按需加载 AnimeScene，保留共享动作状态。通过构建依赖图确保 native 静态依赖不包含 Three.js；相同画布 transform 不重复写 DOM，继续刷新热点和执行前检查。

## 验收

记录未改动 baseline 构建；对照 static dependency 字节与 Chrome 原生加载资源/GPU 初始化。回归覆盖成功加载、加载取消、原生失败与 context loss、sleep/wake、恢复、键盘/触控选择、412×960。完成 TypeScript、生产构建和相关测试后上线 Web，保留旧首页及所有版本化安装包。

## 完成结果

- TypeScript 与生产构建通过，聚焦回归 52/52、完整测试 1603/1603 通过，无失败、取消或跳过。独立菜单复核的 17 项相关测试也通过。
- 构建静态依赖图：原生角色所需未压缩 JavaScript 从 889,067 bytes 降至 345,785 bytes，减少 543,282 bytes（61.11%）。这是角色静态依赖，排除动态备用模块与模型资产，并非整页传输大小或加载耗时提升。
- 公网 Chrome 原生成功路径创建/峰值 GPU 上下文从 baseline 2/2 降至 1/1；未请求 Three.js、AnimeScene 或备用表情集。使用真实 Core 6 与 MOC v5 的 V12 角色；没有变更人物贴图、比例或 MOC。
- 真实页面 412×960，文档宽度 412，无横向溢出。触控打开模型菜单保持按钮焦点，关闭按钮 44×44；隔离真实组件页面验证键盘搜索、方向键与 Enter 选择。正式账号模型及默认项未改。
- 实际上下文丢失后才请求备用模块与 Three.js。原生、备用、恢复三个阶段均保留 sleep；点击“恢复动画”只重建人物，再用 Enter 唤醒正常。长按测试通过真实页面的键盘事件注入，唤醒通过 Playwright 键盘操作。
- 在任务 Chrome 标签页阻断备用脚本请求，再触发 context loss，外层错误边界显示静态人物及“刷新恢复动画”，消息输入仍可用，整页未崩溃。随后清除网络阻断与缓存诊断并验证正常恢复。
- Web 已原子部署到既有服务，公网首页、14 个新增资源及 MOC 共 16 项均 HTTP 200，完整字节 SHA-256 与候选相同。旧首页留有私有备份，V12 MOC SHA-256 保持 c174352f594b1823bdb9cc14b503d64f41cd2be58d9baa6c4dc82450c93c6195。
