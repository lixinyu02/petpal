## 当前方向：补强真实 Cubism 模型

用户纠正：要补强 Cubism 模型，不能把完整立绘回退作为结果。V7 新增独立 `reference-layered` 作者 profile，以 `artwork/akari/idle.png` 为唯一中性母稿，保留原脸、眼睛与刘海的比例及像素。机械分解头、躯干、两侧发梢，从同人物表情母稿提取局部闭眼、A/O 嘴型及情绪覆片；它们是原生 ArtMesh、实际参数关键形与父变形器，由真实 MOC/Core 绘制，不能整图换帧。头身连接的过渡顶点固定，脸与覆片共享头部坐标；仅在实际姿态中无拉扯、重影及接缝后恢复默认 Cubism。保留原 profile 和历次候选，不修改冻结作者工具。

V7 已通过 source／Core／Chrome／语音验收并上线网页，具体范围见 [V7 验收](../cubism/reference-layered-validation.md)。当前能力以局部原生覆片、协调小幅动作及发梢为准；没有连续眼睑或独立眼球视线，官方 Editor 打开／保存／再导出及实体设备不在已完成范围。下面保留各轮历史设计，不能把旧能力和旧结果转写为 V7。

## 历史临时处置：恢复完整原人物

用户连续否定 V5 和 V6 的整体神态。V6 新眼睑导致过多眼白暴露，不能继续作为默认交付；几何及像素检查通过也不能证明美术成立。网页默认恢复原 `AnimeScene` 完整立绘动画，保留原角色、表情纹理、眨眼、语音口型及直接互动。它不是完整 Cubism 模型，后者保留为明确未接受的作者候选。先用完整人物在 Chrome 检查中性、互动、说话和 412×960 布局，再原子更新网页。此次不继续缩放或重组五官，不展示拆散的眼部 atlas。

## 背景

用户否定上一轮画面，并明确主要问题是动作时脸、身体被拉扯与五官变形。此前静态拼接修复和参数有限性检查未验证动作中的人物比例；此次保留已有美术，重新处理绑定与参数合成。

后续用户继续明确静态模型存在大额头、头发覆盖不对。V3 虽已消除被测试的动态滑移，不能视为用户接受美术：机械 PSD 中性合成就有中央 134–151 像素额头露肤，两张前发与后发有不同发旋，右前发自带耳朵。优先新建 V4 统一前发资产，保留脸、五官和连续身体，按参考图补足眉毛上方的刘海覆盖，避免硬挪整张头发遮眼。保留 V3 作为动态修复历史候选。

用户随后指出候选眼睛过大，要求接近最初温柔日系少女、奶油白与浅橘的形象。V4 围绕每侧原眼白中心等比缩小眼白、睫毛、虹膜与闭眼层至 85%，虹膜围绕自己的中心额外缩小至 92%；眉、鼻、嘴、脸与原身体保持。统一前发等比注册，不通过压扁头发或移动眼睛改变角色比例。

初查显示头部继承全身非刚性 BodyXY / ZBreath，脸轮廓、五官与头发还会分别叠加不同透视形变；运行时动作和指针跟随使用加法，实际参数可超过任一单独动作，眼球 Form 同时受表情和 jelly physics 影响。以真实 Core 与浏览器对照确认这些因果，不能用简单“缩小所有角度”替代修复。

## 目标

动作中保持同一头部的轮廓、五官、发际线和颈肩关系，轻微转头、眨眼、表情与口型仍可用。保留原美术与现有账号、语音、Agent、下载及更新数据。默认网页候选须先通过实际动态画面验收，再上线。

## 方案

在同一 issue 内先冻结当前 v2，制作固定参数／组合姿态浏览器检查页。独立 authoring runner 通过冻结工具的公开 API 创建新的稳定人物 profile，编辑不协调的全身、脸部和发际关键形，避免非等比和重复透视；禁用使眼部扭曲的 jelly 输出，仅保留独立发梢运动。保留 classic 与 continuous-body 的重建合同。

运行时明确互动动作拥有参数的优先级，避免指针把 Nod / Shake / TapHead / Greet 推出作者验证区间；必要时按当前内置 rig 限制组合形变。真实 MOC／纹理和源说明放新版本目录，旧目录保持。只有基于实际几何和画面的结论才写入验收记录。

## 影响与风险

改动限定于人物作者工具、模型动作／物理资产、Cubism 参数合成与相关测试。不换人物，不修改冻结 GPL 工具，不重打客户端。自动生成的 CMO3 仍需独立官方 Editor 打开／保存／再导出；几何比例回归不能证明美术效果，应与 Chrome 动态视觉检查并用。

V4 前发通过 imagegen 生成真透明原素材，使用独立 native PSD 打包脚本注册到固定人物画布。机械采样不会涂改生成像素；额头 alpha 覆盖、眼白遮挡、中性整个人物与实际 Chrome 画面分别核对。不能把 V3 的几何通过当作 V4 静态比例通过。

## 验证

检查中性、左右／上下、侧倾、身体组合、指针与动作同时输入、表情和 TTS 能量驱动口型；将面部比例、特征相对位置及颈部连接加入真实 Core 回归。Chrome 检查固定姿态与慢速动画、412×960、停止／隐藏／休息、双实例和异常回退。TS 与隔离生产构建通过后，原子部署静态文件并读回公网 hash；后端与数据保持。源码经公开审计后按既有授权提交推送。

## issue-2：原参考比例与神态复核

用户继续否定 V4，并确认主要问题为整体脸部比例和神态。直接比对原参考、中性 PSD 合成与正式移动网页发现：统一前发比肩长参考延长约 140px、胸前卷发过厚；眼组和虹膜叠加缩小后眉宽未变，瞳心近乎水平，神态偏木；原鼻素材有硬边暗线，下颌轮廓较参考短。此结论不能由上一轮自动化通过否定。
