# OpenUI 教学交互修复

- Date: 2026-10-24
- Complexity: L1
- Status: implementation

## 问题与目标

用户指出 test 账号的欧姆定律对话既未主动选择交互，追问动态交互后又未显示。只读检查确认两条相关记录的助手消息均为 auto；其中四消息记录最后已包含完整 OpenUI，实际校验报两个 Field 数字绑定不符合 string schema，以及一个动态字符串子节点无效。原始对话、账号和凭据仅保留在私有诊断目录，不改写历史。

## 修复范围

按用户补充采用交互优先策略：讲解、计算、比较、计划、步骤和只读卡片等只要现有组件能够合理呈现就主动使用；保留明确纯文本、代码和指定机器格式，不制造空表单和假动作。受控组件兼容有限数值字段、安全标量文本子节点，以及列数完整的一维单行表格，让原历史与真实模型回复直接渲染；不执行模型提供的 JavaScript/HTML/网络动作。输入清空绕开SDK的null作用域缺陷，未绑定控件补齐公开SDK需要的类型信息；回填草稿只显示填写值。输入清空、非法数值与零电阻有可验证行为，新增教学示例使用合法表达式和明确提示，并兼容既有正式客户端的字符串绑定。

组件说明由同一 library 重新生成，补充真实 SDK、SSR 和浏览器输入/预设/明细/流式回归。新增资源在隔离目录构建，避免覆盖线上 dist；通过后受控上线网页和后端，保留既有正式安装包、下载清单、更新签名和业务数据。此任务不移动 v0.9.15，也不自动重打客户端。

## 验收

原 OpenUI 完整片段不改写即可通过校验并显示；修改12V/4Ω得到3A，预设按钮与明细开关有效；新示例拒绝零或非法电阻的误导结果。普通 Markdown/代码与远程动作拒绝保持。用 Chrome 验收候选及正式网页，真实模型验证是否能自主选择交互，区分模型输出质量和前端确定性回归。线上读写仅限本任务所需，保留原记录及全部现有用户配置。
