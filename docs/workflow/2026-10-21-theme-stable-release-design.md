# 四端UI、深浅色与正式版本发布

- Date: 2026-10-21
- Complexity: L2
- Status: building-and-validating

## Goal / Scope

用户要求继续优化UI适配、深浅色，并发布正式版本。本轮将此前已完成的每日陪伴、Magic7/Pro与Magic8适配纳入正式交付，统一检查Web、Android、Windows及Ubuntu（x64/arm64）。按当前正式发布状态选择下一个未使用的补丁版本，不覆盖同名既有正式资产。

## Design

一个完整发布issue：先用真实页面/源码确认主题和响应式问题，再修复语义色/对比度、表单和弹层、移动短屏及原生系统栏。保留淡白默认、手动日夜及既有自动切换偏好；不丢失用户设置、不为机型硬编码缩放。以当前真实可用能力筛选设置项，保留聊天、语音、远程Agent、官方认证、内置代理及桌面工具。

构建使用冻结的同一源码/前端资产；Android提升versionCode，Windows/Ubuntu/Web与发布版本一致。先准备并验证全部产物，再按既有签名升级协议、GitHub正式Release和服务器直接下载源发布。主目录dist合并资产，不清空下载/更新。若有平台实机/原生验证不可执行，明确边界，不把静态文件或交叉打包当运行通过。

## Delivery Transaction

1. 读取当前Git/正式tag/catalog/签名公钥指纹和构建入口，保留回退源与正式发布清单。
2. 完成主题/布局修复，执行相关前端与原生测试；Chrome验收日夜、手机/短屏/横屏与桌面。
3. 冻结版本与源码后分平台构建，校验包内容、签名/哈希、内置runtime和平台原生可执行性。
4. 生成升级签名和正式catalog，先stage再验证；生产维护前确认无运行/排队/未知任务，备份并记录业务及下载/代理/记忆保护状态。
5. 上线网页/后端和正式Release、更新源，验证HTTPS、完整下载回读/哈希和升级签名。失败只按本轮新备份精确回退，不回写旧业务数据。收尾任务进程及维护标记。

## Security / Preservation

不输出API密钥/签名私钥/账号密码，不将私有目录、数据库或凭据打包/提交。确认当前沙箱启动故障后，仅对必要且已授权的检查/构建/发布申请范围明确的自动审查执行。不绕过拒绝；如确被拒绝且无安全替代，再向用户明确行动和原因。

## Validation

主题对比度/颜色、设置与账号隔离、旧客户端兼容、手机键盘/安全区和字体、原生系统栏；最终Web/Windows/Ubuntu/Android包验证；当前签名继承、更新序列单调递增、GitHub与服务器正式下载可达、业务/记忆/代理保留。具体结果写同日期verification。
