# Windows 客户端启动修复

- Date: 2026-09-30
- Complexity: L1
- Status: accepted / implementing

## Background

用户报告其他人双击 Windows 客户端无法启动或闪退。当前 v0.9.0 是 x64 portable EXE，包含内置后端、Codex 与 OpenCLI；每次需要将完整依赖解包到 TEMP，本机先前登录页耗时约 91 秒，网络临时盘已有超时证据。大部分主进程启动异常仅写控制台退出，普通用户无法获知原因。发布资产 hash 一致，尚未收到目标电脑的具体异常信息。

## Goal

复验实际发布 EXE，修复不可见的启动失败与页面加载失败；为普通用户提供解压一次即可启动的 Windows 包，验收干净 profile、中文空格路径与仅系统 PATH，更新公开下载入口。

## Solution

统一启动错误诊断，日志仅记录有限类型、阶段、版本与错误码，不记录凭据、原始数据或任意异常字符串。正常启动也等待主窗口与桌宠页面加载结果。保留用户数据，失败时提示明确修复方向和日志位置。保留便携 EXE，并给解包过程加入可见启动说明；新增 Windows ZIP，将完整运行目录压缩后供用户一次解压。沿用现有登录、权限与签名更新安全边界。

## Impact

桌面启动流程、打包配置、下载中心、Windows 发布资产和对应测试。包含已完成的最新共享前端。仅发布 Windows 修复版，其余平台保持已有包；生产数据和 RK3566 固件不修改。

## Risks

未知发布者提示仍取决于代码签名，不能通过关闭安全保护解决；目标电脑的杀毒拦截或旧 OS 尚不能从本机验收倒推。ZIP 用户必须完整解压而非只复制 EXE。诊断文件应在私有应用目录并限制内容。当前远程账号桌面内置升级限制另行记录，本轮优先处理无法启动。

## Verification Plan

旧发布 EXE 隔离 smoke；启动错误脱敏、失败写日志与页面加载的回归；最终包内容读回、CLI 与 OpenCLI、人物窗口和登录门禁验收；中文空格路径启动；公开发布 hash 与下载目录核对。Chrome 验收下载中心，Windows Computer Use 验收真实窗口，避免操作生产账号数据。
