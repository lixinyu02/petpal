## 仪器自审与解释边界

- `getBoundingClientRect` 只计人物子树内的实际 JavaScript 调用；固定负载初始化自己读取一次 canvas 以生成路径时明确排除。工具栏、报告区和状态更新不纳入 rect／属性统计。
- 属性统计使用真实 `MutationObserver` records，并在样本起止 `takeRecords()`；style 与 data 是全部属性的子集。它统计变更记录，不统计 CSS 内部布局次数、Paint 次数或 GPU 工作，也不等价于每一次 JS setter 调用。
- rAF 仪器没有额外创建 rAF 循环；计数是该夹具窗口实际交付的回调，包含现有30FPS门禁的空检查，不应把约1600回调／10秒解释为160FPS绘制。
- 长任务 API 在本机受支持。表中只计 `startTime` 落在采样窗内的条目；没有覆盖 GPU／合成线程，也没有把“0长任务”解释为无卡顿、无边界跨窗任务或无后台开销。
- 采样前要求可见、真实 Cubism ready；结束时拒绝隐藏、非 Cubism、无绘制推进及不足约10秒的样本。六轮均通过这些门禁。
- 静态服务器只写本轮私有报告；跨来源报告写入被拒绝、读取限制在冻结目录，未提供账号或生产 API。构建与报告不含生产状态、密钥或聊天历史。
- 已自审未发现会推翻这六轮计数的夹具缺陷。测量仍含本身的轻量插桩开销，后续对照必须保留同一夹具及口径。

## 本轮最小优化边界

后续只评估单次 pointer／refresh 操作内复用 rect，以及100ms连续诊断采样、语义立即发布；前两帧诊断就绪契约严格保留。内部动画仍逐帧更新，不以诊断属性采样频率证明 GPU FPS，采样帧计数允许约±3帧的发布边界差异。不做 transform 几何投影、跨操作热点缓存、降帧率、降 DPR／纹理质量或 loader 延迟加载改造。
